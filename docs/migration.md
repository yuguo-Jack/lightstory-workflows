# 接入已有安装与移动仓库

新用户直接按[安装](installation.md)配置。已有ComfyUI、Skill和第三方节点可复用，不必重复下载权重或应用。

## 接入已有环境

1. 在`config/local.json`填写实际应用、模型、输入输出、画布和工具位置。
2. 对已安装的第三方源码，用`dependency_paths`按ID登记；`doctor`/`deps fetch`只读核对固定版本和补丁，不重置已有安装。不匹配时先审查差异或为新版本选独立位置。
3. 执行Skill/节点/画布安装计划。相同内容保留，同名不同内容报冲突。先备份和比较需要替换的旧入口，再按既有授权切换。
4. 通用UI保留原生可编辑副本，来源和哈希登记在`state_root/installed/workflows.json`。已有模型栏目可显式设置`installation.workflow_namespace`为空字符串；新用户默认`LightStory`。
5. 核对客户端发现的Skill、原生UI、节点导入及目标工作流。服务由原启动器管理时先复用，避免同一安装同时运行两个后端。

## 移动本仓库

editable安装和符号链接依赖源码真实位置，不能直接移动后就假定可用。停止本工程管理的活动任务，在新位置重新执行editable安装，更新配置中的绝对路径，并逐一修正自己管理的Skill/节点链接、启动快捷方式或计划任务。原生UI副本仍在原位置，更新其来源登记。

最后从工程外目录运行`python -m lightstory paths`、`doctor`和目标请求准备，核对链接及工具路径。只在无消费者仍依赖旧位置后移除旧副本。备份和历史资料放忽略的私有目录，明确无返工/回退用途后再按[清理规则](maintenance.md)处理。
