# 游戏制作主线

完整方法和模板维护在[Game Production Workflows](../skills/game-production-workflows/SKILL.md)。本文作为项目使用导航，不复制底层模型参数。

| 阶段 | 实际推进与产物 | 执行入口与检查 |
|---|---|---|
| 输入与范围 | 玩法、视角、平台、画质/帧率、内容量、美术样例、交付要求；记录假设和决定 | Game总流程；按需game-design-theory、game-art-direction、game-ui-design |
| 路线与分工 | Web/Unreal运行路线；生成/Blender/引擎/现有素材分工；依赖、授权和风险 | runtime-selection、asset-production；Web进入Game Studio，UE进入unreal-mcp或已确认的引擎操作路线 |
| 可玩灰盒 | 玩家、镜头、移动、核心决策/规则与最少UI；能真实试玩 | 选定运行端；不先批量堆美术素材 |
| 垂直切片 | 一个代表场景、一段完整交互、一套角色/音画达到目标品质，验证生产可重复 | Comfy + Blender +运行端逐层验收；硬点先试 |
| 内容生产 | 角色/道具/场景、2D/UI资产、绑定/动画/声音/视频，按资产版本和目标端预算批量制作 | 复杂2D可以生图加后处理；规则构件可直接Blender/引擎；3D生成后仍处理拓扑、UV、材质和导出 |
| 游戏系统与集成 | 输入、相机、交互/碰撞、AI、进度、存档、界面状态、声音、关卡和演出 | UE或Web执行层；实测读写、状态恢复与极端输入 |
| 打磨与性能 | 可读性、角色手感、灯光/材质一致性、LOD/预算、加载与稳定性 | Blender优化与真实运行端测量，记录硬件/版本/帧时间；生成任务不并发干扰测试 |
| 发布验收 | 独立启动构建、操作说明、资产/许可清单、实际试玩与问题记录 | 打包版本检查，不能用PIE/开发服务器或截图替代 |
| 更新与清理 | 变更影响、回归、迁移与返工依赖；及时清理无用临时文件 | 同一项目状态和资产清单，保留源文件、可用构建和必要证据 |

## 常用资产链

- 图片/角色概念 → Qwen；最终图检查身份、文字、比例和参考职责。
- 静态3D → Pixal单图先看外观，参考不一致时多图可能更差；合格GLB进入Blender修形、拓扑、UV/材质、优化和导出。
- 自动骨架/蒙皮 → SkinTokens按对象适用性；普通人形也可Mixamo/Rigify；机械分件/坦克部件可直接Blender/引擎建立确定性层级和关节，不把人形动作提取器用于机械。
- 常见动作 → Mixamo动作库或已有合法动作；真人表演复现 → Motion分支；精确接触、手持点、道具、脚底与循环 → Blender/UE修正。
- 面部布线、表情与口型 → Blender专项及运行端方案；静态生成模型不自动获得动画拓扑或可靠表情。
- 过场/片头/背景视频 → Video总流程，交回格式、音轨、时长/帧率、版本和游戏播放/跳过/循环要求；游戏端继续验收。

## 原方法保留的关键点

用户玩法和审美是需求依据；先路线、灰盒与切片，再扩产。各子任务沿用同一项目，不递归立项。执行通过、资产合格、目标端正确和完整游戏验收分别记录。新会话读落盘材料恢复，不依赖旧聊天附件。必要的制作增长可保留，不因固定磁盘预警擅自降低质量或删依赖。
