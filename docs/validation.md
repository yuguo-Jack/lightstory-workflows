# 验证、证据与限制

## 三种不同结论

1. **原主机历史模型能力**：原库81图中72项GPU运行成功、7项Pixal历史GPU成功但旧样片已清理、2项CPU辅助成功；原主机4080 16GB/32GB RAM，具体规模和质量限制保留在Comfy Skill。公开摘要见[historical-summary.json](evidence/historical-summary.json)，私人原始素材和大型工程不分发。
2. **本工程移植检查**：配置解析、UI/API完整性、节点/模型来源、脚本语法、路径/隐私、隔离Skill/画布安装、请求准备、补丁与转换等。它不新增GPU画质或影片/游戏成品结论。
3. **新用户/新作品验收**：自己的环境和输入必须实际运行、观看/试听、Blender/引擎回读、打包/整片检查；不能继承原主机passed。

## 开发检查

当前版本的源码与宿主检查见[发布记录](evidence/release-checks.json)及仓库CI，与历史模型证据分别记录。

```powershell
python tools/lightstory.py validate
python -B -X utf8 -m unittest discover -s tests -v
```

测试不访问收费服务、下载真实权重、打开编辑器或启动模型；使用本项目临时目录中的合成小文件和隔离目标。CI运行相同宿主检查。原生自定义节点依赖Comfy/Torch接口，仅做源文件/登记检查，不通过import它们在无GPU测试机上伪造执行成功。

## 新机器的代表性验收

| 能力 | 最小真实验收 | 仍需单独检查 |
|---|---|---|
| Qwen | 文生图、参考编辑、蒙版与Alpha；用到分镜/控制时再测对应分支 | 小物体、文字、身份、控制/蒙版坐标、链式漂移和LoRA配套 |
| Pixal | 代表单图GLB+PBR；需要双/四图时用一致参考比较 | 几何/材质、孔洞、法线/UV、背面、拓扑、可动画性与运行端预算 |
| SkinTokens | 静态GLB→骨架/蒙皮，保几何/PBR与变形检查 | 既有骨架补权重、动物/机械适用性、命名、极端形变、目标引擎 |
| H3 | 所选家族的短片；需连续/控制/编辑/放大时逐项验证 | 身份衣服、接点、音频、动作接触、蒙版时序、参考与噪声表 |
| TTS/Music | 短句/短曲实际试听、内容及文件技术检查 | 音色/表演、长文接点、歌词、动态/响度、最终混音 |
| Motion | 合格单人短片、rig匹配、动作回读与材质 | 手指、足滑、根运动、握点/道具、自交与许可 |
| Game/Video | 独立可运行游戏构建/真实成片完整检查 | 玩法体验、目标硬件性能、全局一致性和用户主观评审 |

变更只验证受影响的代表分支。不要因使用一个Skill重跑所有旧测试，也不要为“全部通过”修改阈值、隐藏失败或降低用户要求。

## 发布检查范围

宿主测试覆盖配置和路径、非覆盖安装、上游Skill组装、节点补丁、请求隔离、下载断点/校验、Next-Scene转换、图编写往返、H3功能静默回退、媒体完整解码和可选历史预览。独立源码副本必须在缺少维护者私有配置与资料时通过同样检查。

完整前端回读、Blender资产质量、UE/MCP连接和GPU品质需要真实环境与素材，不在无GPU宿主CI中伪造通过。已有固定依赖和模型文件可只读核对；存在、大小匹配及历史SHA记录，与本次重新计算全部权重SHA是不同结论。
