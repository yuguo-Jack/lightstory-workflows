# 统一维护、更新与空间管理

源码是统一维护入口。Skill与自创节点可用链接，第三方原生安装通过配置登记，UI保留可编辑副本并记录维护源。接入已有安装或移动仓库见[迁移说明](migration.md)，不自动替换冲突内容。

## 改哪一层

| 改动 | 维护位置与同步 |
|---|---|
| 制作阶段、交接、质量/清理方法 | 相应Game/Video Skill及模板；相关文档只作导航，避免复制一套操作配方 |
| 模型使用、配套、注意事项 | Comfy Skill对应reference，必要时同步模型/节点lock和UI/API |
| 通用画布 | UI和API成对更新、catalog、节点需求/来源、模型清单和输入占位要求 |
| 具体影片/游戏 | 项目目录；定制图在原生Projects/<ID>，不把角色/关卡写进通用库 |
| 第三方升级 | 改固定revision，审查上游diff和许可，重新评估patch，保留实际检验记录 |
| 本机安装路径 | config/local.json，不把私有路径写回公开Skill或脚本 |
| 插件/MCP接口变化 | 对应客户端官方插件与集成文档；实际schema为准 |

## 推荐更新顺序

1. 在本地分支做一个相关主题，保留用户已确认的内容与当前可用版本。
2. 查看本次差异、版本/许可与消费者，决定受影响分支；改代码、模板或画布，必要时更新lock和声明。
3. 执行静态/隔离测试；真实模型或引擎能力变更再用代表素材实测，记录未通过项。
4. 更新CHANGELOG、兼容说明和必要截图/去私有信息摘要；成品截图只在有分发权时加入。
5. 审阅后本地commit；只有用户明确授权发布时才检查GitHub账号/远端并推送。

第三方checkout不跟随main自动漂移；发布包不包含获取到的巨大依赖缓存。第三方源码与用户原生安装不相互覆盖，合并补丁需结合固定基线验证。

目录变动后运行`python tools/build_docs.py`重建总览；命令行为和实际写入边界见[命令参考](commands.md)。

## 维护者导出

原生ComfyUI里改了画布时，把当前目录登记JSON作为输入，导出到新的快照目录审阅，再按变更范围更新仓库。保留UI/API采样参数与连接，清除机器路径、素材名和嵌入预览；来源、修改和受影响验收都要更新。维护工具不会自动将原机历史状态当作新发布版通过。

## 定期清理规则

- 每批生成、渲染、构建及阶段结束后检查；连续工作至少每**2小时**检查。
- 临时增长**30GiB**、累计**60GiB**，或相关盘可用空间低于**60GiB**时提前盘点；确有制作用途的增长可以保留，阈值不是强制删除线。
- 范围覆盖项目runtime/下载/抽帧/转码/模拟缓存，以及本任务实际使用的Comfy原生temp、output/H3分段、Motion工具原生outputs和编辑器中间缓存。
- 保留模型、用户原件、源资产、成品、可用工程/构建、小型证据和待返工消费者仍需的数据。
- `.lightstory/skills`是安装依赖，外部工具/模型缓存可共享，不能把整个`.lightstory`、tools、models、input或output整库清空。
- 可选的私有历史档案和安装回退副本不进入Git；明确无回退/证据/素材用途后再处理，不能仅凭目录名判断可删。
- 先查任务、进程、引用、真实路径、链接/硬链接、属性和占用；只删除已确认无用的任务所有文件，使用原生命令和LiteralPath，不加Force、不绕过策略拒绝。
- 删除后检查依赖并记录实际可用空间变化。移到别处或删除硬链接不等于回收同等磁盘空间。

`python tools/lightstory.py cleanup --project <项目绝对路径>`只盘点候选，不做删除。真正清理按上述归属规则执行，不能由目录名推断全部文件都无用。
