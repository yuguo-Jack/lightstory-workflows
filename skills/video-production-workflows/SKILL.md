# Video Production Workflows

这是本机视频制作的总入口。将用户的剧本、参考、审美和交付目标变成可执行的分镜及成片，按现有成果继续工作。质量来自美术定稿、全片动态分镜、样片校准、分镜挑片、局部返工、合成、剪辑和真实播放验收；不以模型一次输出作为完成标准。

用户提供剧本、审美/风格、时长和分辨率等目标并要求成片后，默认由执行者补齐技术方案并持续做到可交付影片：选择模型与镜头路线、补充必要参考、制作关键帧/预演、配音配乐、挑片返工、剪辑合成和导出。已授权的普通制作步骤不逐项索要批准；不把分镜文档、孤立片段或“工具已安装”作为最终结果。关键要求无法达到时继续评估可控替代路线，保留用户要求；确实缺能力/素材或成本超出授权时明确说明，不默默删掉关键内容或无限重复失败请求。

## 分工与调用边界

本技能维护整片的内容/风格依据、镜头与素材计划、路线和质量取舍、调度、剪辑/合成/声音、导出与验收。生成只是其中一种制作方式；已有合格素材、实拍/录屏、确定性CG和图形动效可直接进入生产，不强制每镜过H3。

`$comfyui-local-workflows`独立负责具体模型任务的选配、素材预处理、有效请求、运行排错、单项产物审查及其缓存清理；模型文件/采样/节点/接口和技术限制在该技能维护，本总流程不再另存一套操作配方。Blender和CapCut各由其专用技能负责真实工程操作。类型技能及`$h3-prompt-writing`提供创作/提示方法，运行仍交给对应执行技能。

调用ComfyUI时交出镜头/资产目标、职责明确的参考、规格/容差、项目目录和保留依赖，收回真实产物及检查/限制；沿用同一项目，不另建嵌套影片。交接见[项目内任务交接](references/project-operations.md#模型任务交接与验收分工)。模型任务通过后，本技能仍负责跨镜头及整片验收，不能把单项`passed`提升为成片完成。只要求一项生图/视频/声音或3D生成时可直接调用ComfyUI技能，不强制启动本总流程。

## 开始或继续

1. 先读当前项目的制作简报、风格与连续性记录、分镜计划和运行状态；沿用已选素材，避免换会话后从头生成。新项目放 `${PROJECTS_ROOT}/<视频项目>`，临时文件在其 `runtime`，正式模型及 ComfyUI 画布留原生目录。
2. 从用户信息确定用途、观众、剧本/核心信息、目标时长、比例、审美参考、语言与声音、交付尺寸及编辑器。已给出的选择直接采用；普通缺项给出合理假设继续，只有真正影响路线且无法推断的选择才询问。模板见 [制作简报](assets/production-brief.md)。
3. 读 [本机能力与入口](references/local-environment.md)，使用Comfy模型时由 `$comfyui-local-workflows` 按其runtime/cleanup规则检查服务、队列和资源；只用CG/编辑器时检查相应工具，不为此启动Comfy。按[项目空间管理](references/project-operations.md)登记磁盘基线、临时目录、缓存归属与保留用途。优先现有合格素材和本地能力；不因类型技能提到其他模型就自动安装或切到付费云生成。

使用ComfyUI时优先复用能满足要求的通用画布；仅换素材、提示词或参数的任务保留项目运行副本。确需改节点/流程时，以最接近的现有画布另存定制版，放入原生工作流栏目`Projects/<项目ID>/<模型>/<功能>.json`，不覆盖通用模板。来源、修改、UI/API、验收与清理归属按[画布复用与项目定制](references/project-operations.md#comfyui-画布复用与项目定制)记录；作为游戏视频子任务时沿用父项目ID和目录。模型/节点安装更新、通用画布补充及验收属于能力维护，其通用画布归模型/功能栏目，验收样片不因此成为影片制作项目。

执行时可按需组合本机系统命令行工具、系统 Python 环境及其库、自编脚本、技能和插件。FFmpeg/ffprobe 只是常用示例，工具选择不限于本技能列出的入口；采用适合任务且可验证的方式，简单确定性处理可以直接完成。环境选择和文件约定见[本机工具使用原则](references/local-environment.md#本机命令行与-python-工具)。

## 制作主线

按项目规模裁剪，不机械制作无用文档或固定数量的镜头。

1. **锁定内容、交付与质量依据。** 提取剧本关键含义、人物、品牌事实和不能改变的要求；把审美样例转成可检查的光色、造型、材质、构图、运动和节奏目标。区分交付尺寸、实际生成尺寸和可接受的修复范围。
2. **按需完成视觉开发。** 已有合格素材先复用；需要生成或改造时，用Qwen制作/编辑角色、服装、道具和场景定稿，选定风格样张及逐镜构图关键帧。沿用布局可选Fun边缘/深度控制，设计下一镜可用Next-Scene并逐镜筛查。检查身份、比例、数量、光影和可用运动空间；分镜静帧不等于视频真实结束帧。生图贯穿前期与返工，不只用于封面，也不强制每片重新生图。
3. **先安排可剪的全片时间线。** 新叙事或复杂片段用分镜图配临时对白/主音乐构成有真实时长的animatic，必要时嵌入Blender白模，验证故事、动作时间和节奏；已有素材剪辑可直接粗剪，简单短片可合并试片。以[shot-plan.json](assets/shot-plan.json)按需记录计划、整数帧和实际素材；它不是可直接POST的API请求。
4. **验证难点并逐镜选路线。** 身份近景、复杂动作、主风格和镜头接点优先试片，记录所需时间/资源；按镜头选文生、首帧/首尾帧、多参考、视频编辑、确定性 CG 或合成。首次使用本项目的制作/交付链，或关键工具/格式改变时，将代表样片走完导入、必要后期、声音、导出及目标播放器的[完整链路校准](references/finishing.md#批量前的完整链路校准)。已校准且未变化的链路不重复测试；短小简单片可合并试片，复杂长片按场景分批推进。
5. **充分编写提示词，再生成和选片。** 按[提示词编写与检查](references/prompt-direction.md)将主体/场景、光材质、动作表演、运镜和声音写细；已选类型或Flova风格方法必须体现在本次实际正文，不能只写技能名或停在风格文档。H3按官方对应模式指南组织完整提示，Comfy执行者核对生效字段再提交。记录参考、种子、参数、实际时长和选片原因，按同一目标审查真实结果。失败只处理受影响镜头及其依赖；连续长镜头先检查少量接点，不用独立分镜拼接冒充无缝。试片成功的参考与风格版本贯穿后续生产。
6. **粗剪、合成与精修。** 实际时间线上先解决故事、节奏和主声音；对选片做必要的跟踪/动态遮罩、CG/分层合成、局部修复与精修，再做统一调色、音乐拟音、字幕和包装。送修和返回按[镜头交接与回套](references/editing.md#镜头交接与回套)核对版本、源范围及剪辑位置；修改后复查运动、遮挡、投影和声音，不用静帧贴补冒充时序修复。
7. **导出并验收实际文件。** 核对全片及接点、首尾、关键细节、口型和声音；技术探测可用 [scripts/media_qc.py](scripts/media_qc.py)。草稿保存、缩略图和探测通过不能代替完整观看或导出。
8. **交付和清理。** 提供可打开成片、需要的可编辑项目及必要素材、参数/选片记录和已知限制。按 [项目与收尾](references/project-operations.md)清理已无返工作用的大缓存，保留模型、原件、成品和必要返工数据。

## 必须保持的边界

- **制作期间持续管理空间**：按[项目与收尾](references/project-operations.md#制作期间的定期空间管理)执行每批/阶段及连续工作期间的检查节奏和预警值，覆盖项目与实际工具原生目录；已确认无用途的大临时文件当轮清理。必要增长可保留，空间足够时继续，不因预警擅自暂停或降品质。Comfy执行者返回其模型缓存处理结果，本技能协调全项目消费者，防止下游尚需使用的素材/缓存被提前删除。

- 配方以4080 16GB / 32GB RAM为资源基准，重GPU阶段串行；其他配置先校准。分页增加提交余量，不能代替显存；不能关闭保护或把持续失败当成通过。
- H3 是生成模型。参考/LoRA/语义约束不能保证人物、手持物、物理接触、文字、口型或相机轨迹完全精确；检查实际运动，必要时换短镜头、改变覆盖或用确定性 CG/合成。
- Blender的RGB普通参考传达运动意图；需要逐帧结构依据时，将规范深度/姿态/边缘序列接入H3 Fun ControlNet。两者都不直接执行`.blend`的相机、骨骼或物理，结构控制也不保证精确接触/几何。硬要求保留Blender实际渲染路线；Fun单镜头链不等于导演台任意多段控制已经接通。
- CapCut 云端草稿和本地桌面工程不是同一份项目。按用户选定目标使用匹配工具；涉及云上传、收费或发布时遵守当前明确授权和插件要求。
- 不把最终画布或文档当成成片，不把 1080p 导出尺寸说成原生 1080p 生成，也不保证任意长度无缝、精确对嘴或所有风格都已实测。
- 上游类型技能的审美默认可被用户覆盖。新视频不默认套动画、英文文案、歌词、BGM或字幕；只有适用的环节才加入。

核对日期、上游版本、公开参考范围与维护方式见 [sources.md](references/sources.md)。本技能安装验证不等于已制作并验收某一部影片。
