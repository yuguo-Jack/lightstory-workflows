# 按镜头选路线与全流程覆盖

以用户目标和已测样片选路线。完整影片可以混合多个路线；不要求所有镜头都走同一模型，也不要求把下列所有工序塞进每个项目。

## 常见生产路线

| 路线 | 更适合 | 本机实现/检查 |
|---|---|---|
| 已有合格素材 → 剪辑/必要后期 | 用户实拍、录屏、现成镜头或已有CG已满足内容 | 直接使用并保留来源/版本，检查技术规格和引用，不为使用模型而重新生成 |
| 文本 → 视频 | 外观限制少、探索运动/气氛、建立镜头 | H3 01/02，检查构图和动作，而不是只看提示词是否详细 |
| 视觉定稿 → 分镜关键帧 → 图生视频 | 固定人物、产品、风格或需要先看构图 | Qwen 01/02/03/04 → H3 03/04/05/18；人物/场景锚点共享，关键帧逐镜对应 |
| 多模态参考 → 视频 | 外观、动作、运镜、音色来自不同素材 | H3 05/18；分别绑定引用职责，不假设所有条件都硬锁 |
| 既有视频 → 编辑/风格化 | 有动作表演/实拍/渲染源片，想改外观或内容 | H3 06/07；逐项核对保留与变化，局部未必严格受限 |
| Blender预演 → 参考/结构控制生成 | 空间、相机和动作节奏先明确 | RGB软参考，或规范深度/骨架/边缘片→H3 Fun结构控制；外观图另供，仍非确定性执行 |
| CG动画/模拟 → 渲染 → 合成 | 物理、人数、产品结构、路径有硬要求 | Blender实际动画/渲染/合成；必要资产另做，Pixal静态网格不自带完整角色动画 |
| 图片/文字/录屏 → 2D或2.5D动效 | 解说、信息图、标题、品牌、插画/照片叙事 | Qwen美术 + CapCut/Blender关键帧与图形；真实界面可录制，不把推拉图当人物表演 |
| 分镜批量 → 编辑成片 | 剧情、广告、MV、纪录及大多数较长作品 | 独立镜头依连续性/声音/切点形成整片；有效选片后再精修 |
| 连续分段 → 长镜头 | 必须连续穿越/跟拍的同一时空 | H3 10/11，先查少量接点；不承诺任意长度无缝 |

循环片还要检查姿态、速度、照明、相机与声音的循环接点，不能仅令首尾图片相同。真正对嘴/唱歌片要单独验证口型；不能把参考音频或ASR当对嘴系统。

## 工序覆盖与真实状态

“有制作方法”“软件原生能做”“本机模型已运行过”“本片已验收”是四种不同状态。

| 工序 | 本机职责 | 还需注意 |
|---|---|---|
| 开发/制片 | 剧本拆解、目标/质量依据、难点、资源与交付计划 | 用现有用户材料补齐技术决策，不暗改主观要求 |
| 概念美术/视觉开发 | Qwen角色/场景/道具/色光样张 | 图片生成已测；本片角色和风格必须新验 |
| 故事板/关键帧 | Qwen逐镜构图、可选Next-Scene下一镜、Fun结构控制、参考编辑和局部修复 | 单镜画面与角色库区分；不把九宫格直接当首帧；Next-Scene不锁身份/三维几何 |
| 动态分镜/声音预演 | 静帧 + 临时对白/音乐 + 简单运动组成真实时长预览 | 方法可用；按项目实际输出animatic，不只写表格 |
| 空间/动作预演 | Blender白模、相机、动作/模拟 | 已安装Blender；具体复杂交互和H3遵从性需试片 |
| 生产采样/选片 | Comfy执行对应H3模式、参考/控制/可选适配器并返回实际素材，本流程选片 | 运行/核心功能/内容约束分开；当前范围读执行索引，不将已测模板外推全部组合 |
| 局部返工/镜头覆盖 | Qwen先修静帧，H3重做镜头/短段，剪辑调节 | 避免关键要求被反应镜头或转场悄悄省略 |
| 跟踪/动态遮罩/合成 | Blender + 正确素材/底板/CG；简单叠层CapCut | 属于按片实现的制作工序，非已验证一键自动修复节点 |
| 图形/标题/屏幕替换 | CapCut/Blender确定性排版与动画 | 精确文字/品牌后期保真，工具能力按当前接口确认 |
| 剪辑/在线回套 | CapCut，FFmpeg辅助代理/转码/合成 | 云端与本地工程分清；最终回到原片，不误交代理 |
| 配音/音乐/声音设计 | Ming、Music3、H3原声及可用拟音 | 已有音频生成证据；精准拟音/口型和长曲无缝另验 |
| 调色/画面收尾 | 选片后的镜间匹配、色彩管理及必要增强 | 生成式二采可能改细节；VSR/专用去闪烁/补帧不假定已部署 |
| 母版/多规格交付 | 实际导出、字幕/无字等按请求、完整观看试听 | 导出尺寸不等于原生生成清晰度；可编辑项目须留引用媒体 |
| 归档/清理 | 成品/源文件/小型记录保留，无用大缓存及时清 | 项目与原生Comfy目录均覆盖，返工缓存完整保留 |

## 从要求到自主完成

用户给出的剧本、风格样例、时长、分辨率倾向足以开始；根据内容自行补充镜头覆盖、视觉素材、声音和后期方案。缺少普通技术参数时说明所选默认继续，不把设备选择、采样器、文件命名等决策退给用户。

先把质量要求落到可观察事项：主角身份/衣服是否一致、关键动作是否完成、风格与样例哪些属性一致、时间是否匹配、字/对白是否准确、成片是否完整可读。按项目重要性排序，不能以更多像素或更多特效代替关键要求。

代表镜头应覆盖主要风险而非只选最容易的一镜；记录实际耗时、内存和可用结果，决定生成尺寸、参考数量、镜头长度与精修策略。4096像素等高分辨率倾向需明确实际生成、后期处理和交付路线；不先承诺4080能原生完成所有高分长镜头。

带完整制作授权时继续完成生成、返工、剪辑、声音、导出与验收；“先分析/只写prompt”则停在请求范围。只有缺关键素材/不可推断选择、需新增收费或能力确实不足时才把具体问题交给用户，不用每阶段重复确认阻断工作。

关键镜头失败：依据缺陷调整有效参考/关键帧/动作/模式 → 需要时试预演/确定性CG或合成 → 保持剧本要求重新检查整片。新尝试应有针对性变化；重复同条件失败不能算持续改进。硬要求与现有工具能力冲突时给出真实差距及可行取舍，不把未解决项标成已达标。

完成标准是：实际可播放成片符合内容、风格与技术目标；关键缺陷已处理，余下限制明确，必要工程/素材可读，收尾完成。方法论提供可重复执行的路线；任意剧本一键、零返工或电影级品质不是当前能力证据。
