# 项目组织、版本与收尾

## 单一项目目录

默认 `${PROJECTS_ROOT}/<视频项目>`，用户给目录则沿用。按实际规模创建下列有用途的子目录，不一次生成全部空目录：

| 路径 | 用途 |
|---|---|
| `brief/` | 制作简报、剧本版本、风格/连续性与最终交付规格 |
| `assets/` | 用户原件、获准参考及必要角色/场景素材，记录来源 |
| `assets/visual-development/` | 已选角色/服装/道具/场景/色光版本及逐镜关键帧，标明职责与受影响镜头 |
| `previs/animatic/` | 有真实时长的全片/分场动态分镜、临时声音与占位素材索引 |
| `previs/` | `.blend`、动作/相机说明、低成本引导视频与关键帧 |
| `compositing/` | 底板、动态遮罩、跟踪/CG场景、可编辑合成源与实际版本 |
| `shots/<镜号>/` | 分镜提示词、请求、结果索引、选片/缺陷；正式媒体可引用原生 output |
| `workflows/comfyui/` | 画布索引、定制版API及运行请求；UI画布存ComfyUI原生项目栏目 |
| `audio/` | 对白、音乐、拟音、最终主轨与对应文字 |
| `edit/` | 剪辑计划、CapCut 工程/云会话索引、源片入出点 |
| `exports/` | 实际交付版本、封面/字幕等 |
| `qa/` | 技术报告、审查表、必要对照帧 |
| `runtime/` | 本任务代理、解码帧、临时音轨、转码/渲染缓存 |

保留正式 ComfyUI `models/input/output/user/workflows` 等原生位置；通用API、启动和保护逻辑由`${LIGHTSTORY_ROOT}`及配置的运行位置管理。不复制模型进视频项目，不重复堆多份原生输出；用索引/路径/哈希追溯，交付独立包时才收集必要媒体。

每个镜头用稳定 ID 和 take，例如 `S010_T02`；提示词、参考、模型/LoRA/种子、有效时间线与 output 路径相互对应。记录计划时长和实际帧数、入点/出点、未完成事项。已通过的镜头不因换会话重跑；返工保存小型差异说明，不无限保存所有大中间量。

## ComfyUI 画布复用与项目定制

1. **先复用，按需要才改流程。** 调用`$comfyui-local-workflows`查询当前通用画布和真实接口。仅需替换素材、提示词、种子、尺寸、时长或已有可调参数时，沿用现有流程，项目内保存本次配置/API请求；不为每个镜头或take在ComfyUI新增一份画布。
2. **确需定制时从现有画布派生。** 需要不同节点连接、参考/声音组合或处理阶段时，选最接近的通用画布另存，记录必要差异，保持所用模型、采样和输入接口配套。不覆盖模型分类下的通用模板，也不从零重搭已有可用部分。
3. **定制UI统一放原生项目栏目。** 先核对当前实例、用户及工作流根目录；本机当前默认根目录为`${COMFYUI_ROOT}/user/default/workflows`。其下按`Projects/<项目ID>/<模型>/<功能>.json`组织，项目ID与项目记录一致且不与其他项目重名；画布名描述功能和必要差异。目录按实际需要创建，供用户在ComfyUI工作流浏览器直接打开、区分和后续清理。由游戏总流程调用时沿用父项目ID，不按技能、镜头或每次运行另建项目根目录。
4. **UI与执行请求一致。** 项目`workflows/comfyui/`保存对应API及索引，关联原通用画布、修改原因/内容、原生UI路径、输入/输出/缓存归属和验收状态。API JSON不能代替可编辑UI画布；定制完成要在ComfyUI中检查加载、接线和实际生效输入，用本次代表镜头验证受影响流程。执行成功与画面/声音质量分别审查，不因新建项目重跑整个通用库。
5. **按项目管理版本与清理。** 复用同一拓扑时更新参数/运行记录，不无限堆叠同功能完整画布。保留当前可用定制UI、匹配API和必要依赖；它们是项目源文件，不按临时缓存默认删除。废弃版本及大缓存按本项目清理规则处理；以后清除项目画布时，只操作核对归属的`Projects/<项目ID>`范围，不连带删除通用画布、模型、成品或其他项目。

## 任务状态与调度

### 模型任务交接与验收分工

本项目给出镜号/资产ID、叙事或素材目标、已选参考及职责、生成/交付规格与容差、项目请求目录、保留依赖和优先级。Comfy执行技能决定与当前模板匹配的参数、输入绑定和预处理，返回真实产物、状态、元数据、内容检查/偏差、实际请求及缓存保留项。详细最小交接约定只维护在[Comfy运行参考](../../comfyui-local-workflows/references/runtime.md#任务与结果交接)，不在这里再定义另一套模型请求格式。

提示文档保存本次充分展开的最终正文、采用的模式/风格依据及参考分工；`shot-plan.json`沿用已有`prompt_document`与`api_request`关联，不再复制一套正文/接口字段。提交前由执行者完成[实际生效核对](../../comfyui-local-workflows/references/runtime.md#提示词与实际请求核对)，在原记录注明必要问题和处理。外部Group/内部时间线发生改写时，回传实际最终文本及绑定，不仅交回改写前的意图。模型执行通过后仍按同一关键内容与风格目标选片。

请求及回执沿用`shots/<镜号>`或项目已有素材目录；调用`prepare`时显式指定项目内`--out`，输出保持独立原生前缀并由项目索引引用。执行者不另建影片、不重设用户风格，也不因完成一段模型视频再次递归启动Video。已有游戏父项目时继续共用其ID/目录。

Comfy检查运行、文件/模型指令及本项素材；本技能据镜头目标决定是否选片，安排局部返工、后期及与前后镜头的关系。最后仍做整片正常速度播放/试听和交付检查。执行成功、内容约束是否满足和艺术/技术验收分开记录；技术通过但内容不合格的take不自动进入正式剪辑。

轻量项目用一份镜头/选片记录即可；不强制每项生成附一套新表。批量按镜号/take跟踪已成功项和失败原因，参数/参考更新时只处理受影响依赖，避免重排全部已选素材。

每次提交前记录所属项目、镜号、请求路径、独立 output 前缀和 H3 `cache_name`。提交后补 `prompt_id`、状态和产物。准备请求不等于提交；history 成功不等于视觉通过。提交超时/中断后先查询，不重复排队或清用户队列。

重GPU步骤在项目层统一串行，普通文档/剪辑计划可继续；不要让不同执行技能各自启动H3、Qwen、Music、Cycles或UE重渲染互相挤占。底层服务、队列和内存故障由对应执行技能诊断；本技能按返回证据调整镜头路线/安排，不重复实现启动器或降低保护阈值。

先用代表镜头估计采样/预处理/后期时间和空间，按片长与质量优先级分批生产；不将全部时间用于无关候选。每次返工对应一个缺陷和具体变化；新结果仍未改善时重新判断素材、控制/CG/合成路线，不无限同条件尝试。质量、时间或容量确有冲突时说明真实差距与可行安排，保留用户关键要求。

## 制作期间的定期空间管理

用户已授权在制作过程中及时清理确认不再使用的临时大文件。空间检查和实际清理贯穿生产，不以整片完成为前提；它由执行本技能的agent在工作期间执行，不自动创建定时任务或后台删除服务。

### 检查时点与预算

- 开始/恢复项目时记录相关磁盘可用空间、本次临时目录及缓存组的大小。优先扫描登记的项目/任务目录和实际原生输出/缓存，不反复遍历整盘或模型库。
- 每批生图/生视频、Blender渲染/模拟、音轨转换、合成或导出完成后，先验收/挑片，再清理明确废弃的数据，然后继续下一批。失败/中断后也要检查大残留，保存错误摘要后处理。
- 连续工作期间至少每2小时检查一次；有任务运行时可检查空间，只清理已证明隔离且没有消费者的旧数据。长任务用可恢复的查询/轮询插入检查；工具调用暂时无法检查时，返回后立即补查。不为清理终止活动任务或用户进程。
- 默认预警：已登记的临时数据较上次检查增长30 GiB，或合计超过60 GiB，或任一相关盘可用空间低于60 GiB，任一满足就提前盘点/处理。大任务写入前还需预估额外峰值，并留至少10GiB余量；空间不够时先处理，不能盲目提交下一批。
- 这些数值触发盘点，不要求一定清理或把占用降回阈值以内。确认增长来自必要素材、活动任务、工程依赖或返工数据时可以全部保留，记录用途并将本轮标为“无需清理”。实际剩余空间足以容纳后续写入峰值和余量时继续工作，无需因预警暂停、改批量或降品质；只有实际容量不足时才调整批量/存储安排。正式素材、模型和工程大小不计入“无用临时文件”；运行中的大缓存即使超过预算也不能删。
- 每个阶段结束，以及本轮工作停止、项目暂停/交接前，再检查一次；续作从上次存储记录和保留用途恢复，避免另一个会话重复生成或无限堆叠。

### 当轮清理和保留判断

把每组大文件归为：活动任务/仍被消费、工程依赖/正式素材、必要返工缓存、已废弃临时数据、归属未明。确认废弃者当轮清理，不只列候选；其他类别标明用途。保留项记录路径、大小、消费者/用途及下一次检查时点或结束条件，不能仅写“以后可能有用”。

优先回收已拒绝且不再比较的试跑、旧计划的完整H3缓存组、无用途的解码帧/代理/临时音轨、已合并导出的重复中间文件、失败后不再恢复的映射/渲染残留及无用途打包副本。需要同计划续拍、二采、局部重算时保留其完整必要H3缓存组，不能每出一段就删掉后面还要读取的内容。

已选素材和备用素材只保留本项目确有用途的版本；无依据不复制整份输出/帧序列作为“每步备份”。工程仍引用的文件先重连/烘焙到稳定位置并验证，再删旧副本。不要清完再让编辑器重新解码/生成同一份大缓存。

范围同时覆盖项目`runtime`、本次ComfyUI原生input/output/temp、实际H3段缓存、Blender序列/模拟缓存，以及本地CapCut中能确认归属和无用途的代理/渲染缓存；CapCut私有工程只用受支持清理方式或已核对路径，不猜目录整删。以下收尾分类与Windows规则同样适用于每次周期清理。

保留一份小型存储记录：检查时间、各盘可用空间、临时目录总量/增量、大目录/文件及归属、实际删除清单、保留理由和下一次检查。清理后复查成品/工程依赖，记录观测到的磁盘空闲变化；硬链接、稀疏/映射文件和其他进程写入会影响实际回收，不能用文件长度冒充回收量。

如果安全清理后仍无法满足下一批写入需求，先停新增大写入，继续不依赖空间的工作，并报告具体占用、必要保留项和可行安排。锁定或策略拒绝按下文处理，不使用强制选项、换壳或改属性绕过。

## 收尾规则

沿用 `$comfyui-local-workflows` 的 `references/cleanup.md`。任务结束执行最后一轮检查；制作期间已经按上述规则持续清理，不把所有大临时文件拖到交付。覆盖项目和Comfy原生位置，执行者要实际完成。

最终收尾先确认制作任务结束、成品可读、工程/素材引用完整及是否还有明确续拍或返工。制作期间清理只需确认对应数据的生产者/消费者已经释放且后续无需读取，不要求整个影片任务结束。候选包括：

- 当前项目 `runtime` 下无用途的代理、抽帧、解码序列、临时渲染、混音/转码副本。
- 配置的`${STATE_ROOT}/runtime/jobs`中本任务临时数据和本次实际`--temp-directory`中残留。
- 配置的`${STATE_ROOT}/runtime/cache/h3/<本次缓存名>_<节点ID>`；默认 Desktop 后端可能改用实际 output 的 `minimax_seg_cache`，两者按当前配置检查。
- 原生 input/output 下本任务专属前缀中的废弃转换/试跑数据；保留最终图/视频/音频和仍被工程引用的素材。
- Blender 本任务已无返工用途的图像序列/模拟缓存；保存源 `.blend` 与必要绑定数据。CapCut 自己产生的代理/渲染缓存按其受支持的清理功能或已核对位置处理，不能乱删私有草稿内部资源。

**保留**模型/LoRA/编码器/VAE及共享权重缓存、用户原件、成品、可编辑工程及引用媒体、小型参数/错误/选片/清理记录。仍需同计划分段返工/二采/续拍的 H3 缓存保留完整组，登记路径/大小/用途与结束条件；MP4 不能重建完全相同的潜变量缓存。

不要把`${LIGHTSTORY_ROOT}`或`${STATE_ROOT}`整目录、Comfy `.venv/custom_nodes/user`、共享下载器、其他项目、浏览器登录资料或模型缓存当作本次临时文件。也不为“可能以后要用”永久囤积所有失败试跑；返工完成后处理对应大缓存。

## Windows 安全清理

先列精确路径、大小和归属，解析绝对路径并验证仍位于已授权任务/实际缓存边界；检查重解析点、硬链接、只读属性和锁。使用原生 PowerShell `Remove-Item -LiteralPath`，目录确需递归才加 `-Recurse`，**不加 Force，不跨 shell 拼删除命令，不绕过策略拒绝**。

锁定文件等消费者正常退出，不结束归属不明进程；拦截仍未解决时保留并报告确切原因/可复核命令。清后验证成品/依赖可读，比较实际磁盘空闲空间，不能拿硬链接标称大小冒充回收量。`/free` 卸载内存不等于清磁盘。
