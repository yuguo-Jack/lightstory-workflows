# H3镜头制作、连续性与返工



本页负责影片里的镜头选路、创作输入、选片与返工依赖。具体权重、LoRA/ControlNet配套、采样、节点字段、有效Group/时间线、提交/导出和运行排错，由`$comfyui-local-workflows`按当前画布执行；不在总流程维护第二套操作配方。



## 先按镜头目标选路线



普通H3承担完整通用制作、专项动作/运镜、后处理及既有定稿接续；Flex是广泛创作中画面表现与效率的另一候选；Turbo适合匹配条件的少步探索。三路符合本片目标都可成片，不按步数或总榜排固定高低。详细优势/弱项、作者要求与本机实际边界分别读Comfy执行技能的[H3与三路选择](../../comfyui-local-workflows/references/h3.md)、[Flex](../../comfyui-local-workflows/references/h3-pika-flex.md)及[LoRA/连续性](../../comfyui-local-workflows/references/h3-lora-continuity.md)。



| 本镜需要 | 交给执行技能的功能方向 |

|---|---|

| 外观自由、探索气氛/构图 | 文字生成，普通01、匹配Turbo02或Flex文字入口 |

| 明确起点或起终构图 | 首帧/首尾帧03/04或对应Flex；两端要在给定时间内可合理连接 |

| 人物/道具外观加动作、运镜或声音依据 | 多模态参考05/18或Flex参考入口；每份素材职责单独登记 |

| 修改已有片段 | 源视频/参考编辑06/07或Flex编辑；保留原片，明确改变和保留项 |

| 沿用白模/源片逐帧结构 | Fun结构控制的深度/边缘/姿态入口；原片、控制、蒙版按同一时窗和坐标准备 |

| 局部外观修改并保护其他区域 | Fun局部重绘入口；动态蒙版和必要投影上下文，由[合成修复](compositing-and-repair.md)统筹边缘与时序 |

| 多个可剪的独立镜头 | 分镜批量或外部多组输入08/09；不把自动拼接当连续时空 |

| 必须延续同一时空的长镜头 | 普通10/11或Flex连续入口；先确认少量接点再扩展 |

| 已选片需要精修/放大/局部修脸 | 对应后处理12–17；先看缺陷是否适合生成式再处理，不对全片默认打开 |

| 专项人物表演、风格、动作/运镜、环绕或换机位 | 先明确镜头目的，再选[专项入口](../../comfyui-local-workflows/references/h3-extra-loras.md)或原动作预设；不堆满LoRA |



高要求的物理接触、复杂动作、多场景一致性、光照材质或参考运动，按代表镜头比较普通/Flex等候选；硬要求仍不足时选Blender实际动画/渲染或合成。普通配套更完整不等于每项模型画质领先，Flex官方展示也不是本机所有复杂场景都已通过。



## 创作输入与任务交接



由本流程交出本镜叙事作用、景别、主要动作的起点/过程/终点、相机意图、声音发生点、已选身份/服装/光色锚点，以及允许和不允许改变的内容。对白长度与可用时长匹配，关键动作留在可剪区间。



新写或实质改写提示词时使用`$h3-prompt-writing`并读取对应模式指南，充分展开本镜画面、动作阶段、表演、运镜及声音；已选类型/风格技能的指导要具体写入正文。内容展开及示例见[提示词编写](prompt-direction.md)，本页不复制另一套H3语法。每份输入标注身份、风格、关键帧、运动、结构或声音职责。执行技能负责把提示中的引用对应到真实槽位，核对当前家族与有效参数，不能由总流程凭记忆拼节点ID或时间线私有字段。



`shot-plan.json`是镜头/选片记录，不是可POST的API。将镜头/资产任务交给Comfy执行技能，沿用本项目的请求位置和产物索引，收回实际文件、元数据、参数/运行记录、内容偏差与缓存保留项。具体合同见[项目内交接](project-operations.md#模型任务交接与验收分工)。需要修正生效字段或定位显存/队列故障时回到执行技能，不在两边各维护一套排错流程。



## 尺寸、时长与参考的制作决策



区分用户交付尺寸、实际生成尺寸和后期放大；按构图、难点和资源试片选择，不把一份历史样片规格当作所有任务默认，也不承诺更高分辨率/更多参考一定容纳。可用配方及已测范围只从Comfy当前索引和模型参考读取。



以返回的真实尺寸、FPS、帧数和时长安排剪辑/声音。模型帧桶可能使输出不同于请求秒数；计划使用整数帧，入出点以源素材实际时间基准记录，不能将多个近似秒数累加。更改输出比例时重审构图，不能只拉伸主体；参考/控制片需要重采样时保留原件及其变换记录。



参考数量先满足职责，不以填满端口为目标。出现身份/姿态冲突时回到少量可靠锚点逐项加条件；下一镜静帧不自动是上一镜真实尾帧，骨架/深度也不定义脸和衣服。具体对齐和控制边界见[视觉开发](image-development.md)及[白模预演](blender-previs.md)。



## 两种长片及接点



**分镜长片**由独立景别、场景和机位组成，靠角色/场景锚点、视线、银幕方向、动作匹配、声音桥和切点连续。可以明确硬切；不要强行把不同场景用首尾帧变形连起来。各镜可按需要选不同制作路线，再统一成片。



**连续长镜头**继承历史画面/声音延续同一动作与空间。先做少量相邻段，检查人物、服装、背景、相机、动作阶段、声音和每个接点，再扩展。跨段改变LoRA/风格可能增加跳变；同一连续链尽量保持兼容路线，具体全局/分组配套由执行技能处理，不能用同种子替代上下文。



Fun、CrossView等原生专用控制链不自动具备导演台任意分段时间窗处理。交给执行技能核实该镜控制输入和连续方案，不能把整条控制视频全局接MODEL后就宣称长片无缝控制。若该组合未验证，先按独立镜头制作或验证受影响的少量接点；精准轨迹/握持仍可用确定性CG。



## 选片、局部返工与后处理



- 按镜头目标审查真实运动/声音，区分技术执行、核心功能和内容约束；保留已选take及偏差。只有实际达到本片要求的素材才进正式剪辑。

- 失败要定位身份、物件、接触、背景、字形、口型、闪烁、风格或节奏。针对问题调整参考/控制/提示或路线；不重复同条件盲跑，也不因一个失败重生全片。候选探索与故障修复分开记录。

- 同一连续计划局部返工时，向执行者交出原计划/缓存与需改变的段落，保留其他依赖。中段结尾变化会影响后段上下文，检查前后两侧，必要时顺序重做受影响后段；新版本不能误命中旧缓存。

- 现有二采/放大入口主要处理同次生成链的一采结果，不会自动读取另一个工作流先前生成的MP4。交回实际素材和返工意图，由执行技能选择同链后处理、源视频编辑、Fun局部或项目定制；需保潜变量继续返工时先保留，不先删缓存。

- 放大、二采、脸修可能改身份/小结构或产生时序边缘；先比较有意义的局部样片。精确文字/Logo/数字用后期准确叠层；高精度接触用CG/合成，不能靠提高分辨率或更多LoRA保证。

- 主声音、字幕、镜间调色和最终导出继续走[声音](audio.md)、[剪辑](editing.md)及[成片验收](finishing.md)。任务完成与缓存清理分开核对，见[项目收尾](project-operations.md)。
