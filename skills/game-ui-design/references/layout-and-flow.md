# 游戏界面的布局、状态与运行检查

Modified 2026-11-01 from the upstream Game UI/UX material; engine-neutral adaptation. See [sources](sources.md).

## 先列决策，再分配空间

HUD优先呈现改变即时行动的信息：当前状态、风险、可执行操作和结果。即时战斗、经营比较、解谜线索、叙事选择的信息密度不同；不用同一种“极简”覆盖全部类型。区分紧急信息、持续参考和按需详情，隐藏策略不能妨碍玩家决策。

世界内UI需要检查遮挡、距离、视角、反光及文字大小；必要时提供屏幕空间替代。俯视群体场景还要考虑血条/选框聚集、同队与敌队语义和重叠优先级。

## 布局与视觉语义

- 选择参考分辨率、锚定/容器和宽高比策略；像素风明确整数缩放及最小可用画布。不要把固定像素定位或某个缩放模式当所有引擎/类型通用规则。
- 关键元素遵守目标平台实际安全区；装饰可以出血。窗口尺寸、UI比例和输入变化后重新计算适用布局。
- 将字号、图标轮廓、色彩语义、间距、面板与反馈定义为一套样式规则。危险/可交互/已选状态不能只靠颜色区分。
- 用中文、长翻译、长物品名和大字号检查裁切/溢出。支持范围内保留文本缩放、必要的对比与减少动态效果选项；具体字号与平台要求依项目验证。
- 在实际游戏尺寸和观看距离判断，不把4K设计图缩在开发窗口的效果当电视/掌机可读证明。

## 状态与输入所有权

每个界面记录适用状态：正常、空、锁定、禁用、冷却、选中、焦点、悬停、按下、加载、成功、错误。异步失败应能重试或退出；重复提交不得消耗两次资源。

对每个打开/关闭路径确定：谁接收输入、是否暂停世界、鼠标是否捕获、默认焦点、返回到哪里。弹窗内约束输入，关闭后恢复合理焦点；不要用一组互相矛盾的布尔值拼出界面流。屏幕栈/状态机均可，按工程选择。

手柄/键盘焦点可见、方向关系可预测；网格边界有意选择环绕或停止。鼠标切换回来也能用。操作提示来自当前动作映射和重绑定结果，而不是写死“按E”后遗漏手柄。

## 数据、资源与验收

HUD读取聚焦的数据源或ViewModel；事件/信号推送变化通常比每帧查询所有状态合适，持续变化值按实际更新需要处理。动画与提示不能覆盖正确的源状态。

复杂插画或生成图做视觉资源，文字、数值和可交互控件独立；检查Alpha边缘、图集留白、九宫格拉伸、图标缩小时的辨识。不要将整张菜单截图作为“已实现UI”。

运行至少覆盖相关路径：首次进入 → 游玩 → 暂停/设置 → 返回；失败/重试；切场景；设备或分辨率切换；窗口失焦；保存/重开后的设置恢复。检查最差背景与代表性负载。完成清单说明实际设备/分辨率和未测范围，非项目支持项不强制扩充。
