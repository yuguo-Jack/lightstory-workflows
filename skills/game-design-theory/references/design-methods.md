# 玩法分析与可验证设计

## 从体验反推规则，再用运行结果检验

MDA用于连接 Mechanics（规则、行动与系统）、Dynamics（规则在运行中产生的行为）及 Aesthetics（玩家体验）。设计时可从目标体验反推需要的行为与规则；试玩时检查规则是否真产生了该行为。它是分析视角，不是“一套机制必然让玩家有某种情绪”的公式。[原始论文](https://www.cs.northwestern.edu/~hunicke/pubs/MDA.pdf)。

例如想要“谨慎探索”，可以比较信息揭示、退路、资源或风险的不同安排；不能直接认定提高敌人伤害就产生该体验。还要检查玩家是否看到线索、理解选择并有恢复机会。

## 按问题选工具

| 问题 | 需要查清 | 最小有效试验 |
|---|---|---|
| 核心行为空洞或重复 | 行动、反馈、结果和下一次决策如何连接；重复是否带来新信息或掌握 | 用最少内容走完整循环，对比一个关键变化 |
| 选项形同虚设 | 代价、收益、信息、时机和情境；有没有支配策略或无用选项 | 在不同情境尝试真实备选，记录为何选择 |
| 难度突变或失败不明 | 预告、输入要求、反馈、知识、检查点及恢复成本 | 复现失败，再只改提示/规则/参数中相关部分 |
| 进度拖沓或内容堆砌 | 技能掌握、能力、内容和叙事进展分别提供什么；是否需要长期循环 | 走一段有代表性的会话，标记重复劳动与新决策 |
| 经济失控 | 按实际项目列来源、消耗、库存、时间、转换和边界；有无无限套利 | 用表格/系统Python模拟候选参数，再在游戏中确认行为 |
| 教学或目标难理解 | 玩家何时知道目标、能做什么、如何判断后果 | 不额外口头解释地观察首次进入，区分未看到与不理解 |
| 手感不好 | 输入到可见响应、运动/镜头、碰撞、动画衔接与反馈分别是否正确 | 重复触发具体动作，在代表帧率与输入设备下比较 |

资源、等级、对抗、奖励和自动难度都不是所有游戏的必选项。竞技平衡、非对称协作、解谜确定性和自由表达需要不同目标。“所有选项数值相同”也不等于平衡。

## 写可推翻的假设

将“更好玩”具体化为：在什么场景，哪项变化，预期玩家能做出什么行为或理解什么信息。记录基线与候选版本、受控条件、观察和反例。试玩人数、时长和指标由风险及可用条件决定；不要凭空把某个数字设成行业合格线。

同时看玩家做了什么、为何这样做、是否理解，以及主观反馈。完成率或游玩时长单独不能证明享受；系统日志也不能读出真实情绪。没有玩家反馈时，保留“实现验证通过，体验待评审”。

## 内容、关卡、叙事与教学

下表是按场景补设计细节的方法，不是要求每个项目同时具备战斗、剧情、等级和经济。已有合格内容沿用；具体实现留所选引擎与对应制作技能。

| 项目需要 | 把主观意图变成什么 | 运行时重点检查 |
|---|---|---|
| 任务、对白与叙事 | 体验/主题、角色动机、玩家知道什么、任务进入条件、选择及状态后果；用稳定ID关联对白/字幕与事件 | 分支与汇合、跳过/打断、条件顺序、失败/重试、重复触发、存档恢复；文字写完不等于任务接通 |
| 关卡、遭遇或解谜 | 每段的目标/决策、路径与视线、线索与操作空间、挑战/休整、反馈与恢复点 | 可达与可解、软锁、遗漏线索、替代路径；遭遇不必是战斗，氛围也不靠强制加敌人实现 |
| 进度、技能与资源 | 能力/内容/叙事或玩家掌握分别怎样发展，选项取舍与资源流；调参依据留项目配置 | 支配策略、数值膨胀、无限套利、重复劳动；短篇叙事不必套无限成长或长期留存循环 |
| 首次体验与教学 | 先让玩家看懂目标，再在真实操作中引入必要规则，提供实践、反馈与可恢复的失败 | 不靠作者口头讲解能否继续、提示是否用真实键位、返回后是否忘记状态；不规定所有类型同一教学时长 |
| 手感与音画反馈 | 动作意图、前摇/响应/恢复、命中或交互事件，以及相应动画/声音/特效/UI | 输入与碰撞先正确；震动、镜头晃动、停顿或闪光不遮挡关键信息、不替代规则，强度可按需要调整 |
| 批量与程序内容 | 可复用模板的变量、条件、边界和合法变体；保留变体/随机种子与版本 | 第二个不同内容是否仍成立、是否出现无解/不可达或违背风格；数量不能代替决策差异与品质 |

故事、视觉与玩法有取舍时，先给少量可审阅变体或可玩片段，说明分别服务什么用户目标；不擅自改主题或补进不需要的系统。需要全套剧情/关卡时把内容工作登记进生产范围，不能只交一个灰盒示例后算结束。

## 将决定交给生产

项目记录至少能回答：保留哪条用户意图、选用什么规则、为什么、实现到哪里、证据是什么、尚未确定什么。数据驱动的调参放项目配置；美术/声音/UI沿用同一事件和语义，关卡安排提供规则可发挥的情境。修改核心规则后检查这些依赖，而不是仅更新GDD。
