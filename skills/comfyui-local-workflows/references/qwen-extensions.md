# Qwen-Image 2.1：结构控制、分镜与可选人物 LoRA



本页补充基础生图/参考编辑，不替代 [Qwen基础用法](qwen.md)。正式画布仍按 `Qwen-Image 2.1/<功能分组>/<功能>` 归档；所有示例可换输入，不是特定角色/影片工程。运行和清理遵从 [runtime](runtime.md) / [cleanup](cleanup.md)。



在ComfyUI打开对应画布，先在输入图片节点上传/选择自己的素材，再改目标描述和种子。工程版的`UPLOAD_*`是待绑定输入，原主机验证图片不随源码分发。新装模型后若旧浏览器仍报“缺失模型”，刷新界面后重新选择；不要因此重复下载已校验权重。运行后看右侧保存节点和实际文件，不能只看左侧控制预览。



## 按目标选择



| 目标 | 通用画布 | 应传入什么 |

## Fun ControlNet Union：结构不是外观参考



底模、Qwen3-VL编码器与RGBA VAE沿用基础画布。控制权重为 Comfy-Org 重打包的 `qwen_image_2.1_fun_controlnet_union_int8_convrot.safetensors`，约3.52GiB；这是已存在文件的校验复用，不重复下载完整7GB级源精度权重。放在原生 `models/model_patches`，由 `Load Model Patch → Apply Fun ControlNet` 加载。本机后者类名仍为 `ZImageFunControlnet`，实际已支持Qwen2.1，不必因此换Z-Image底模。



作者支持 Canny、Depth、Grayscale、HED、Lineart、MLSD、Pose、Scribble 八类和局部重绘；Union指一份权重可接这些输入，不是默认同时叠加八种。控制图由对应预处理器或Blender提供，权重本身不负责自动估计全部信号。普通照片应先提取所需控制图；不要把普通RGB、伪彩色深度或骨架图不加区分地交换使用。



- 边缘重点保形状；深度重点保前后/体积，不能据此保证身份、服装、字形、小单位数量或所有几何一一准确。用图像参考提供外观时要另接正确参考支路，不能让控制图兼任身份照片。

- 本机基准：Euler/simple、40步、CFG1、控制强度1、作用区间0–1、batch1；参考/控制画布关闭KV缓存。作者示例也用40步、控制1；降低强度可放松结构，不把提高强度当成无条件提质。

- 输入、控制、蒙版和输出必须使用同一画布坐标/裁切。当前示例832×480，优先32对齐。局部画布用两个Int节点统一宽高，原图/控制/蒙版支路同时缩放，蒙版用nearest；异尺寸输入也经过同一变换。先选合适比例，不拉伸人物来凑尺寸。原图与蒙版本来不同坐标时，统一缩放无法修正错误对齐。

- 自动深度画布复用已有MoGe2（level4、batch1）。单目深度是估计，先看保存的控制图；玻璃、反射、细枝、遮挡、天空可能错。Blender固定相机/尺度的真实深度可替代估计图，近白远黑，固定整张/整段的映射范围。

- 局部重绘把原图接 `inpaint_image`，蒙版接 `mask`，控制图接 `image`；文字描述完整目标画面。模板分别保存模型原始结果与蒙版外保护后的结果，不能用合成后的像素一致证明模型本身完全不改背景。纯黑区可严格保护，边缘融合、阴影和遮挡仍需看图；改物体时蒙版包含必要接触/投影上下文。



## Next-Scene：静帧分镜，不是连续视频



采用作者推荐的根目录 `next_scene_step2500.safetensors`（约320MiB），不使用 `checkpoints/` 下ai-toolkit原始MLP命名版本。它偏向电影场景、环境和建立镜头的延展/揭示/切景；静态肖像不是训练重点，也不是可精确恢复未知背面的三维相机。作者训练画布512²，本机较大尺寸试片可用不等于所有大画布都稳定。



本机发现根目录文件的 `diffusion_model.` 前缀导致融合MLP的两半未全部匹配。正式使用 `next_scene_step2500_comfy21.safetensors`：仅规范模块前缀，全部448个张量的数据区与作者文件逐字节相同；原件、来源SHA256及兼容副本SHA256/转换证明保留。不能忽略 `lora key not loaded` 后只因能出图就判通过。



正式画布通过已安装的上游 `ViggleTurboLora` 做运行时LoRA计算，避免直接把增量写回INT8权重；这里仅借用加载器，**未加载Viggle加速LoRA、未启用Turbo或六步采样**。依赖文件是原生custom_nodes下的`viggle_turbo.py`，来源/固定版本见下文；缺节点时恢复该文件并重启空闲后端。实测合并/运行时两种加载在某些种子下都可能颗粒明显，所以不能把加载方式当成唯一画质原因，更不能声称它消除了所有颗粒。



作者配方：单镜强度0.7–0.9，示例28步、CFG1；40步亦用于作者对照。本机选40步、CFG1、强度0.7、Euler/simple，按原图的编辑latent尺寸采样。单镜示例seed42，种子不与特定素材绑定；新任务仍应按目标试片。指令先说明下一镜头的推拉、横移、景别/切点，再说明主体动作/环境变化及必须保留项。需要保持某种光线/服装时逐镜明确，不让“下一镜”默认改时间、天气或角色。



链式故事板按 `输出 → 下一镜参考` 接续，作者建议强度≤0.7、每次回接约0.5px高斯模糊，减少第3–4次接续的颗粒反馈；本机使用原生Gaussian ImageBlur。原始输出各自保存，模糊仅作用于下次输入，不覆盖交付图。本例四镜使用42/45/46/47后较干净；此前同一seed42长链出现颗粒累积，seed43单镜也有明显颗粒。遇到问题按镜换种子、降低变换难度、从干净锚点开分支，而不是盲目加步数或无限回接。长链仍可能积累身份、地理和光色漂移；多角色/产品严格一致需外观库和逐镜筛查，不能声称锁身份。



### 操作与本机实测



打开`分镜/01`，替换起始图和`Next Scene:`指令，选择下一镜机位后运行；认可的PNG再进入下一镜或视频生产。`分镜/02`在四行里分别修改提示词和种子，可截取已认可镜头另开分支；模板是四镜示例，不强制所有影片用四镜。保持图像编码器给出的尺寸，若需指定交付尺寸另行记录预处理。



例如：`Next Scene: Cut to a wider three-quarter view, revealing the path to the right. Keep the same person, jacket, weather and lighting.` 每镜明确一个主要机位/叙事变化，不把一张图写成整段多镜视频。要的是同一镜末帧时用基础参考编辑准备合理终点；要的是精确新机位时用Blender相机/结构依据，不能指望分镜LoRA恢复真实三维。



| 功能 | 本例实际耗时 | 观察与限制 |

|---|---:|---|

| 边缘控制 | 12.1秒 | 大布局/轮廓更接近白模；人物朝向、台阶及基座仍被重解释 |

| 自动深度控制 | 14.1秒 | 保留主要空间层次；地面高度/材质可能被补造 |

| 结构局部重绘 | 12.3秒 | 箱体改色，预处理后蒙版外RGB最大差0；异尺寸输入1664×960→832×480另测14.2秒同样为0 |

| 下一镜 | 28.2秒 | 干净近景，服装/世界大意延续；不能认证精确身份及未知几何 |

| 四镜接续 | 102.5秒 | 四张完整PNG；第三镜未完全达到指定高机位，末镜石拱变化 |

| TheseAlpacas v2人物适配 | 18.1秒 | 配方/补丁完整执行，与无LoRA对照；不作为所有人物质量提升证明 |



图像控制样例832×480，分镜1024×576。耗时包含该次编码/采样与保存，不是所有输入的性能保证；旧种子/失败尝试保留诊断记录，不算正式质量通过。



### 接到视频总流程



1. 将剧本拆成镜头目标/景别/动作/时长，确定是独立切镜还是同一连续镜头。

2. 用Qwen基础参考编辑定好角色/场景及首镜；Next-Scene制作下一镜候选，按镜选定PNG，而不是把所有候选都送H3。

3. 独立分镜将各镜PNG分别送H3首帧/参考生成，再剪辑；需要合理起终构图时准备该镜首尾帧。下一镜静帧不是当前镜头的真实结束帧，不能因此保证无缝。

4. 精确动作/运镜需Blender预演时，PNG提供外观/构图，结构控制视频另走 [H3 Fun](h3-controlnet.md)，保持尺寸、帧率、帧数及镜头目标对应。故事板不替代动作表演、时间连续性或声音设计。



## 成人级（NSFW）LoRA：来源、独立配方与验证范围



指定文件为 TheseAlpacas `NSFW LORA | Qwen Image 2.1` v2.0，Civitai模型2958918、版本3357315，约76.1MiB；不是f23gg镜像里的v1。匿名Civitai下载接口要求登录，本次采用公开HF分发文件，SHA256与作者v2文件完全一致；来源与分发位置分别登记，不假称是作者HF仓库。



分类：**成人级（NSFW）LoRA**，依据作者的训练/发布标签，属于可选人物专项，用于静态人物图与关键帧；视频专项的选择见[NSFW快速选型](h3-extra-loras.md#成人级-nsfw-快速选型)。具体输入、输出、对照和验证范围见本批验收记录；分类标签和实际验证结果分别记录。



作者推荐25步以上、CFG3–6、LoRA0.8–1、`er_sde / beta`，并明确不推荐Euler。当前本机测试采用30步、CFG4、强度0.8；这是独立配方，不能直接沿用基础Qwen的CFG1和Euler/simple，也不把其采样参数反向覆盖结构控制或Next-Scene。保持空队列、一次一个GPU任务；更高CFG可能增加计算量。



本批分别验证结构控制、分镜和人物适配，未把三者堆叠当默认组合。需求确实需要组合时，基于最接近的通用画布做样片，确认加载、采样与内容效果再采用；不要为了“功能全”无关叠加LoRA。
