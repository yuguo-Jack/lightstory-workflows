# 本机操作与排错



## 路径与查询



- 正式安装：`${COMFYUI_ROOT}`，推理由配置的`executables.comfyui_python`执行。

- 通用UI：配置的`workflow_root/<命名空间>/<模型>/<功能>.json`，新安装命名空间默认`LightStory`。

- 项目定制UI：同一工作流根目录下`Projects\<项目ID>\<模型>\<功能>.json`；执行前核对当前实例和用户。

- 模型/输入/输出：分别读取配置的`models_root`、`input_root`、`output_root`，允许不同位置。

- 工程根：`${LIGHTSTORY_ROOT}`。正式UI/API和目录在`workflows`，代码在`src/lightstory`和`adapters`；运行记录与缓存在配置的`${STATE_ROOT}/runtime`。

- 工作流目录及历史验证状态：`${LIGHTSTORY_ROOT}/workflows/catalog.json`；公开验证边界见[validation](../../../docs/validation.md)。新任务使用自己的history与产物检查记录。

- API默认`http://127.0.0.1:8188`，以配置为准；公开文档预览默认`http://127.0.0.1:8192/`。



普通辅助脚本用系统Python，无需为了使用技能安装新环境。查询工具不直接提交GPU：



```powershell

python -m lightstory workflows status

python -m lightstory workflows list --model 'Pixal3D'

python -m lightstory workflows show 'Qwen-Image 2.1/02_单图编辑'

```



`show`返回真实API路径、节点ID与输入。覆盖JSON格式为`{"节点ID":{"输入名":值}}`，不要照抄另一画布ID。`prepare`只写副本：



```powershell

python -m lightstory workflows prepare 'Qwen-Image 2.1/02_单图编辑' --overrides '${PROJECTS_ROOT}\task\overrides.json' --prefix 'jobs/my-edit'

```



默认副本与准备记录在`${STATE_ROOT}\runtime\jobs\<新任务ID>`。可用`--out`指定任务目录里的绝对文件路径；不会覆盖正式模板。已有上层项目时使用`--out <该项目内请求路径>`及该项目的独立输出前缀，不另建内容项目；小型独立任务可直接用默认jobs目录。大型批量任务按需要在`${PROJECTS_ROOT}/<内容任务>`建一个任务根目录。图像、GLB、音视频仍写原生output，以索引关联。H3的`timeline_data`可在覆盖文件中提供完整JSON对象，脚本会转为字符串；有效提示、Group与帧数等按H3参考同步核对。



## 任务与结果交接

GLB、H3功能执行、媒体解码及前端回读辅助见[helpers](../../../docs/helpers.md)。



独立任务从用户请求取得以下信息；上层调用时从其镜头/资产记录取得，缺普通技术参数由本技能按模型配套决定。记录按任务规模裁剪，不要求每张图片先填写完整影片表。



| 交接内容 | 本技能处理 |

|---|---|

| 目标与保留项 | 要生成/改变什么，哪些身份、文字、布局、运动或声音必须保持；已选风格与素材版本不擅自重置 |

| 输入及职责 | 实际文件与参考顺序；身份/风格/关键帧/控制/蒙版/声音分别负责什么，同一裁切、时间窗及FPS如何对齐 |

| 产物与资源 | 图片/GLB/绑定/音视频，期望尺寸/时长/格式；区分模型生成、实际输出与后续交付规格 |

| 归属与依赖 | 项目/镜头/资产ID、请求位置、输出前缀；是否返工、需复用的缓存/已选产物及不能删除的消费者依赖 |



交回：实际产物绝对路径和尺寸/帧数/FPS或音频/3D元数据；通用或定制画布来源、有效请求/种子/关键配方、`prompt_id`与真实状态；内容检查、尚存偏差和有依据的修复选择；保留/已清理缓存及原因。单图等小任务可以一段回复加一个小型记录，不强制多份报告。输出前缀由任务副本决定，以history为准，不把指南的默认`output/<模型>`前缀当作本次硬编码路径。



本技能负责“运行成功、产物可读、模型指令与本次输入效果”的检查，不能只交HTTP成功或旧样例。上层再做跨镜头叙事、整体声音/色光和最终影片验收；上层存在不免除本技能对该素材的检查，也不要求单项任务先通过整片验收。



## 提示词与实际请求核对

有文本条件的任务，按实际模式写完整正文：图像写清本次构图/主体关系、光色材质与修改/保留项；视频展开动作、表演、运镜、时间和声音。已选风格方法应落实到可见/可听细节，不能只写技能名或复制模板口号。独立任务同样执行，不需要先进入Video总流程；上层已交出合格正文时保留其内容与审美，只适配当前模型格式。

- **先核对指南和输入职责。** H3新写/实质改写文本读`$h3-prompt-writing`的相应基础/参考指南，保持规定结构、语言、标签和时间表达；Qwen参考顺序/Next-Scene触发及其他LoRA按各自参考。不同模型不共享一套否定词、权重括号或时间戳语法。
- **检查最终将提交的请求。** 对照当前API/节点连接追踪有效文本输入，确认本次完整正文、素材、参考标签和必要触发词已写入，旧示例和无效引用已清除。H3按[生效位置](h3.md#提示词与素材的生效位置)检查外部Group、完整`timeline_data`及内部段落的覆盖/合并关系；不能只改画布便签、外层全局字段或未连接的文本节点。TTS把台词与音色/情绪控制分开，Music把caption与歌词分开；无文本接口的3D/绑定或后处理支路不增加虚构prompt。
- **记录并按目标检查产物。** 保存实际有效请求及必要绑定说明；上层有提示文档时关联其版本，独立小任务可在原运行记录简述。优先看本次关键内容、风格和修改边界是否成立，而非仅有文件或HTTP成功。过长/冲突时保留关键细节、拆分适当任务或改控制路线，不静默丢掉用户要求。

正文里的镜头/光线/接触描述是生成条件，不保证像素、轨迹或物理精确；精确要求仍需对应结构输入、蒙版、CG/后期及实际审查。本节不另定义API字段，以当前真实图和模型参考为准。

## 素材准备与批量任务



- 用当前节点真实支持的输入。原生媒体选择器可能只枚举input根目录；API能读取某个子目录路径，不代表UI选择器也接受。需要可手动使用的画布时核对当前选项，使用可见的相对文件名或经校验的同内容别名；不移动/覆盖用户原件。新装权重后先刷新节点列表，避免因旧界面缓存重复下载。

- 图像先确定比例、坐标、通道与参考职责；蒙版白改黑保，透明PNG核对真实Alpha。长视频先在本任务目录截取所需时窗、统一必要FPS，再送解码节点，避免先整片解码占满内存。音频截取与参考转写保持一致；具体要求读对应模型参考。

- 批量用一份项目/任务清单，逐项标明输入、目标、种子/版本、请求和输出；不为每项新建项目根目录。按已选参数先做代表输入，再串行推进；不把多项独立请求误设成显存更高的模型batch。

- 不同素材可逐项配置，成功项保留，失败项记录原因后只重试受影响项。提交超时先找已入队任务。仅换种子用于候选探索不等于修复；重复资源/兼容故障先诊断，不盲目重排全批次。

- 本机CLI、系统Python与其库可用于转码、裁切、遮罩、文件/媒体检查和API编排；依赖及安装遵循主机规则，正式Comfy推理仍使用其自身运行环境。



## 画布复用与项目定制



先按任务性质归档：安装模型/节点、增加或维护通用能力及其验收，属于**能力补充**；通过的通用画布按`<模型>/<功能或功能分组>.json`归入原生通用栏目，测试素材/请求/样片留验证工作目录，不因此创建生成项目或强制放Projects。按具体素材、剧本、资产或影片目标交付内容，才属于**生成任务**，项目特化画布使用下面的Projects规则。能力补充需要改进通用画布时保留可追溯来源和验收，不覆盖无关功能或把测试人物固化为专用流程。



能用通用画布及其可调参数满足目标就直接复用；仅改输入/参数的请求保留在任务目录，不为每个资产、镜头或试跑新增原生UI。具体生成任务需要项目特化节点、连线或处理阶段时，从最接近的现有画布派生，保持模型与采样等配套，在上述`Projects/<项目ID>/<模型>/<功能>.json`另存可编辑UI，不覆盖通用模板；通用能力维护不套用此项目目录规则。



单独生成任务使用稳定且不重名的项目ID；由Game/Video总流程调用时沿用其项目ID和目录。项目内记录原画布来源、必要差异、原生UI及对应API路径和验证状态；定制版按实际路径使用，不假设已自动进入通用库目录。核对UI加载、接线与实际请求一致，并用本次代表输入检查受影响流程，不重跑整个通用库。



从API构造Director画布时，固定宽高应同时保存输出选择器的“自定义”状态；缺少该界面状态可能被默认0.4MP重算。导入后用实际`graphToPrompt`核对宽高、参考、采样和LoRA，不以API文件正确代替UI可用。新增专项预设已按此保存，不需要重跑旧批次。



当前可用定制UI/API属于项目源文件，保留；废弃版本和缓存按任务清理规则处理。清除项目画布时只处理核对归属的`Projects/<项目ID>`范围，不连带删除通用画布或其他项目。



## 服务和内存



先读`/system_stats`和`/queue`。有用户任务时等待，不清空队列或重启；已有8188应复用，不能另开一份共用同一安装与数据库。



| 配置 | 当前适用范围 |

|---|---|

| Balanced | H3、TTS、Music、SkinTokens、复杂Pixal新输入；PyTorch原生注意力、预留4GB显存、关闭节点缓存 |

| Conservative | Qwen五参考实测配置；关闭动态显存，预留4GB、PyTorch注意力 |

| PixalStable | 旧人物Pixal九项回归；复杂机甲1536的分块注意力曾每步约80秒，不作通用速度预期 |

| Default | 不替代上述配置的实测证据 |



### 注意力与其他加速



当前托管后端的Qwen/H3主推理以`--use-pytorch-cross-attention`选择PyTorch SDPA，日志为`Using pytorch attention`。SDPA按精度、输入/遮罩与支持情况选择Flash/cuDNN等内核，不能仅凭开关声称每层都跑Flash。当前没有给这些画布启用SageAttention、xFormers或VSA稀疏注意力；也没有相同条件的速度/画质增益对照。Pixal的低内存条件节点另有分块处理，不能用这一句覆盖所有子模型实现。



INT8/W6A8主权重是量化；Turbo是少步采样配套，Flex另含后训练与六步蒸馏；Qwen缓存和H3段缓存减少重复工作；动作LoRA改变生成倾向。这些都不能直接等同于换了注意力内核。实际部署以现场`/system_stats`、源码及启动日志为准；安装包存在或SkinTokens的Flash日志不能证明Qwen/H3已改用该实现。



空队列且确定由本工程启动器管理时切换：



```powershell

python -m lightstory runtime stop --apply

python -m lightstory runtime start --profile Balanced --apply

```



`runtime start`发现已有服务只复用，不会自动切配置。Desktop自行启动的实例应先在对应应用停止；不终止归属不明的Python。需要公开文档预览时用`python -m lightstory runtime serve`；历史私有验收站点不随本工程分发。



启动器同时运行内存管理进程。Pixal可用RAM低于8GiB、提交余量至少10GiB时，核对托管PID和任务后请求Windows回收可分页驻留页；数据保留、按需从文件/分页读回，可能增加I/O和耗时。RAM低于2.5GiB或提交余量低于6GiB仍中断。其他模型保留原保护逻辑。



回收不在画布JSON内部。只复制画布、另起不匹配的后端或停掉管理进程，不包含此保障。查`runtime/memory_guard.json`的启用标志和同任务ID事件；历史`last_interrupt`不等于新任务失败。`/free`不保证全部CPU堆和映射驻留页立即归还。



2026-10-30实际运行时D盘分页已分配64GiB、系统提交上限约95.84GiB。运行前仍查现场数值，不把配置/历史当作当前状态，也不擅自重启Windows。分页不能替代物理RAM或等速显存。Motion2MixamoRig是外部进程，Comfy保护器不能替它兜底；按Blender专用Skill监控、串行执行。



## 提交与验收



1. 按上节把本次素材放入/上传到当前`input`并核对节点实际可选的相对文件名；检查参考、蒙版、视频时间/FPS及声音转写，不自动沿用模板示例。

2. 新任务使用独立前缀。H3新内容换`cache_name`；只有明确返工同一计划时复用并核对缓存。准备工具默认生成新缓存名，除非显式覆盖。

3. POST `/prompt`：`{"prompt":API对象,"client_id":唯一字符串}`。保存返回的`prompt_id`，再轮询`/history/<prompt_id>`。检查`status_str`及`execution_error`/`execution_interrupted`；HTTP成功不是推理成功。

4. 提交超时先查队列/历史，避免重复POST；失联保存ID并恢复查询，不无限重启重排。

5. 从history中的output元数据定位实际文件。确认没有其他活动/待执行任务后可POST `/free`，内容`{"unload_models":true,"free_memory":true}`；下一个重任务前再查资源。该调用不清理磁盘；按[空间检查与清理](cleanup.md)处理本次无用途的大临时文件，保留模型、成品和待返工缓存。若用户已有其他任务，不为释放本次缓存中断或卸载其活动模型。



| 输出 | 检查 |

|---|---|

| 图片 | 真实尺寸、主体/小目标、文字、参考职责与Alpha；羽化带会混合 |

| GLB | 可读、几何/贴图、正背侧、小部件/孔洞、UV法线；SkinTokens还检查骨架、归一化/漏权重/四影响、原材质与真实变形，进入引擎另验 |

| 音频 | 采样率、声道、时长、静音/爆音、文字与主观听感；ASR不替代音色和情绪审查 |

| 视频 | 真实帧数/FPS/尺寸、有效声音、身份衣服、接点、小结构和运动；不只看文件存在 |



## 失败处理



- 缺节点/权重：确认正式实例、路径和实际节点加载；不要重部署一套环境。

- 更新`.pyd`拒绝访问/数据库冲突：先停占用该安装的后端再更新。

- RAM保护：保留保护，检查同任务ID、启动配置和回收机制，关闭无关重任务，必要时空队列重开；重试有具体依据，失败仍算失败。

- 提交余量不足：查真实分页/提交，不把扩大配置视为已生效。

- CUDA OOM：查其他GPU程序、batch1；按目标调整尺寸/帧数并说明变更，减步数通常不明显降低峰值。

- 后端直接消失：保存日志、版本、请求与资源，区分内存、驱动和扩展，不无限自动重启。

- 用户暂停、取消或修改范围：保留已完成产物、请求ID及断点/缓存归属，只停止本任务；全局中断前先核对当前运行ID，不能误停其他任务。返工或恢复沿用记录，不将已成功批次重新排队。



## 通用能力维护



模型/节点安装、更新和通用画布补充时，先核对现有文件与需求，避免重复部署。记录发布者来源、版本/修订、文件校验与本机兼容改动，按所用底模、量化、编码器/VAE、适配器和采样配套实施。上游配置与本机适配分别说明，不把社区预设说成官方统一最优。



变更只验证受影响的代表功能：实际权重/节点加载、无意外漏载、GPU或CPU执行、输出与内容要求，以及UI加载和`graphToPrompt`有效参数；未测组合保持未测。可恢复地保留必要小型源文件差异，失败时说明当前状态，不覆盖无关通用画布或回退用户新修改。通用画布按模型/功能入库并更新`catalog`；模型/节点没变的文档检查不启动全库推理。完成后按cleanup处理已无恢复用途的下载/安装/验证残留。



Skill可独立提供用法参考；执行时由配置定位本工程的API、适配器和当前应用。源码与已安装链接依赖不能当作临时缓存清理；移动仓库后按工程迁移说明重新核对入口。





辅助ASR不是正式TTS/Music依赖，需要内容识别时按任务准备。历史样片或分段已清理，不影响新任务使用自己的输入和缓存。
