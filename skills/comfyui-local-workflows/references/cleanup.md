# 制作期间与任务收尾的空间管理

适用于本技能的所有图像、3D、视频、TTS和Music任务。用户已要求：任务结束后不再使用的大临时文件及时清理，覆盖工作目录与ComfyUI原生目录；保留模型、成品及仍需返工的缓存。普通已确认归属的任务临时文件无需另行重复询问。此步骤由执行技能的agent完成，不是已安装了定时清理器，也不意味着所有节点自带自动回收。

## 检查节奏与必要增长

单独调用本技能也执行：每批生成、渲染、构建及阶段结束后检查清理；连续工作至少每2小时检查一次。已登记临时数据较上次增长30 GiB、累计超过60 GiB，或相关盘可用空间低于60 GiB，提前盘点。大写入前按预计峰值和实际余量判断容量；只扫描登记的任务路径与实际缓存，不反复遍历整盘模型库。

这些是盘点预警，不是删除上限。确属活动任务、工程依赖、正式素材或必要返工的数据可以全部保留，记录用途；实际空间足以完成后续工作时继续，不因触发预警擅自暂停或降品质。已确认无用途的临时大文件当轮处理；运行中的文件不删除。暂停/续作及最终交付时再检查一次，更新大小、保留原因和下一次检查点。

上层项目存在时共用其空间/缓存记录：本技能处理自己的模型运行残留并返回保留项，上层协调Blender、编辑器及全项目依赖。小任务无需为每轮检查另建多份表；确认没有大临时数据时记录简短结论即可。

## 从任务开始记录归属

- 沿用`library.py prepare`的独立任务ID、输出前缀和H3缓存名。记录`prompt_id`、实际API请求、使用的输入、成品路径和本次产生的临时路径。若使用另一个任务工作目录，也登记其绝对路径。
- 查当前后端的启动参数、`--temp-directory`、输出目录及节点实际缓存配置；不要假定所有实例都使用同一目录。`runtime/process.json`仅在确认仍对应当前进程时作为依据。
- 大临时数据尽量放当前任务的专用子目录。不得仅为方便清理将模型或用户原件搬入临时目录。
- H3缓存与成品分开登记；GLB引用的外部贴图、后续步骤仍要读取的帧/蒙版/音频属于依赖，不能只凭扩展名或所在output目录判断用途。

## 结束时的处理规则

| 类别 | 处理 |
|---|---|
| 正式模型/LoRA、编码器、VAE、抠图及长期使用或工作流依赖的ASR权重 | 保留，包括Hugging Face/torch缓存内实际承载权重的文件；目录叫cache不构成删除理由。下载中的分段和状态也保留 |
| 仅为本次验收临时准备的辅助ASR权重 | 确认不被正式工作流引用、识别已结束且无后续用途后，可连同本任务的专用下载/临时缓存清理；保留转写结果、来源及必要参数。后续新增识别需要重新准备，不影响H3、TTS或Music推理；不能据此清空共享权重库 |
| 用户原始图片/视频/声音、参考图、仍被画布引用的输入 | 保留；本次转换副本仅在确认不再被后续步骤或可交付工作流引用时清理 |
| 成品图/视频/声音、GLB、必要PBR贴图、可编辑源文件与用户选择保留的版本 | 保留；不能把逐帧数据集、纹理或用户要求交付的中间资产误判为缓存 |
| H3仍要续拍、二采、局部返工、断点恢复的段缓存 | 保留完整必要的缓存组、缓存名和计划。记录用途及结束条件；不要拆掉帧/潜变量/索引中的一部分导致缓存失效 |
| 已结束且无续作用途的H3段缓存、废弃试跑缓存 | 成品导出并检查可读后，按本任务的精确缓存目录清理。MP4不能重新构造完全相同的原始潜变量；若还有明确返工计划就先保留 |
| 无用途的抽帧/解码序列、合成临时音轨、临时代理/转换文件、网格映射、重复渲染与打包目录 | 当前任务结束、消费者关闭并确认成品独立可用后清理；不要把可再生副本永久堆进input/output |
| 小型请求、种子/参数、输入与输出索引、错误摘要、清理记录 | 保留一份足以追溯的记录；不为每次清理复制大文件做备份 |
| 共享编译缓存、包下载缓存、旧日志/转储 | 与本次大临时文件区分；小且复用中的CUDA/Triton缓存可保留。过大的废弃版本或本任务崩溃转储，经诊断摘要保存、归属和占用检查后再清理；不动当前进程日志或其他任务 |

返工尚在进行时不是清理整个段缓存的时机。对已经交付且没有待办续作的任务，应清理已确认无用的数据；不要将“以后也许能用”作为无限保留全部试跑缓存的理由。仍保留的大缓存需记录路径、大小和具体用途，在返工完成时再处理。无法判定归属的文件保留并说明，先完成其他明确可清的部分。

## 必须检查的目录

下表C为配置的Comfy根目录，S为可能存在的共享目录。模型、input、output与temp可以分别配置；以当前实例真实路径为准，不要求建立这些候选目录。

| 范围 | 检查与边界 |
|---|---|
| 当前任务自己的工作目录 | 抽帧、临时渲染、拼接、音轨、下载解压副本与一次性测试文件；保留请求记录、说明、用户资料及正式依赖 |
| `${STATE_ROOT}/runtime/jobs/<任务ID>` | 清理该任务的临时子目录；保留小型API/结果/归属记录。不能清空整个jobs或runtime |
| `${STATE_ROOT}/runtime/temp`及本次后端实际temp目录 | Pixal特征映射、Comfy临时预览、系统临时文件。只删已释放且不再有用途的本次文件；Pixal正常路径会回收映射，失败退出后要检查残留 |
| `${STATE_ROOT}/runtime/cache/h3/<本次缓存名>_<节点ID>` | 当前托管启动器通过`COMFYUI_H3_CACHE_DIR`指定的位置；仅清理已结束且无返工用途的任务缓存 |
| `S/output/minimax_seg_cache`、`C/output/minimax_seg_cache`或实际output下同名目录 | 未设置上述环境变量时，上游H3使用当前output目录。不能只查项目目录而遗漏原生output的大缓存，也不能把所有候选都当成当前有效位置 |
| `C/temp`、`S/temp`或启动参数指定的其他temp位置 | 这些是候选位置，需确认实际使用情况；不因文件夹名是temp就整目录清空，避免影响其他活动任务和仍被用户查看的临时预览 |
| 当前任务在原生input/output下的专用前缀 | 确认哪些是交付物、哪些是合成/转换缓存；只清理本任务不再使用的中间文件。最终视频/音频/模型及关联纹理保留 |
| `${MODEL_CACHE_ROOT}\huggingface`、`torch`及其他下载缓存 | 默认作为共享模型资产保留，不纳入每次收尾清空。辅助Whisper下载一次可复用，不是每次都新增一整份 |

`C/custom_nodes`、`.venv`、`user`、数据库、原生workflows、S/models，以及工程的`workflows/skills/src/adapters/docs`和当前进程/保护器记录不属于任务临时文件。不要为回收几个GiB而删掉日常运行依赖。

## 执行顺序

1. 查询当前任务history已结束和`/queue`状态。共享目录有活动任务时等待，或仅处理能证明完全隔离的已结束任务路径；不通过停止其他任务来腾出清理窗口。失败/中断后先留错误摘要，再处理确认不再用于恢复的大残留。
2. 先验证成品可读、引用的外部纹理/音轨/输入仍在，核对后续步骤是否还要返工/续作。必要时完成最终合并导出后再删除中间段。
3. 列出精确候选路径、大小、归属和保留项，解析为绝对路径并确认位于本次已知工作目录/实际原生缓存范围内。检查重解析点、硬链接、只读属性与文件占用，不跨越链接递归清理。
4. 用原生PowerShell `Remove-Item -LiteralPath <已核对的完整路径>`处理文件；需要目录递归时才加`-Recurse`。**不加Force，不跨shell拼接删除命令，不绕过策略拒绝。** 对锁定文件先等待当前消费者正常释放；不要结束归属不明的Python。仍被拦截则保留，报告原因及可复核的精确路径/命令。
5. 删除后核对模型/成品/依赖仍可读，并比较实际磁盘可用空间。硬链接删除可能不释放等量空间，标称大小不能冒充实际回收。保留小型清理记录，交付中简述已回收量、保留的返工缓存及原因。

`POST /free`用于卸载内存/显存对象，不会自动删除H3磁盘分段或本次抽帧目录；完成它不能代替磁盘收尾。不要为了清理磁盘重跑GPU推理。

## 各模型的重点

- Qwen：成品PNG/真实Alpha图保留；不再使用的临时预览、蒙版转换/放大副本可清理，但仍被可交付编辑流程引用的蒙版要保留。
- Pixal：正常任务结束会释放临时`features-<PID>-<UUID>.bin`映射。单/双/四图曾约3/6/12GiB峰值，不代表每次都应长期留下这些文件；异常退出后只清理已确认无进程持有的遗留映射。GLB外链的贴图、未烘焙的源网格不可误删。
- H3：无损分段帧、音频、潜变量、二采前中间量会比最终压缩MP4大很多；分段数、帧数、尺寸和试跑次数都会影响大小。任务结束按用途清，不按一个固定GiB数承诺；需要保留段返工时明确登记。
- TTS/Music：最终WAV/歌曲/分轨按交付要求保留。多角色拼接的临时段、重新编码副本、临时ASR输入在确认无需修改后清理；用于验收的Whisper权重可复用并按模型保留，转写文本留作小型记录。

历史上清理的约4.26GiB来自11组完成验证的H3缓存（约3.81GiB）、已决定不再使用的辅助转写模型缓存（约464MiB）及少量临时文件，不是每个新任务的固定开销。今后的模型保留遵从本规则，不因上次删除了那份辅助模型就每次重复删除下载。
