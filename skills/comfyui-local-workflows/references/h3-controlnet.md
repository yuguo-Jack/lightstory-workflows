# MiniMax H3 Fun ControlNet Union 2.0：视频结构与局部重绘



这是普通H3的一条可选原生控制分支，补在“白模预演/控制视频”和正式生成之间。它与普通r2v软参考、CrossView投影Guide、SemanticBridge以及动作LoRA职责不同，不因安装了任意一个就称其他全部具备。基础选择见 [H3](h3.md)，静帧/故事板见 [Qwen扩展](qwen-extensions.md)。



## 选哪份画布、给什么输入



正式位置为 `MiniMax H3/结构控制`：



| 画布 | 输入 | 主要用途 |

|---|---|---|

| `01_深度与白模运镜` | 已准备的灰度深度视频＋完整镜头描述 | 白模布局、主体运动、相机轨迹与遮挡的逐帧引导；不是只传.blend |

| `02_边缘视频控制` | 普通源视频＋目标描述 | 图内逐帧Canny，保主要轮廓改外观/材质/风格 |

| `03_姿态视频控制` | 已提取/绘制的DWPose式骨架视频＋描述 | 指定人体动作节奏和大姿态；骨架不提供具体身份、服装或道具几何 |

| `04_结构引导视频局部重绘` | 原视频＋同帧控制视频＋随目标运动的白改黑保蒙版视频＋描述 | 指定区域改内容，保留区另有最终合成保护，原始模型结果也保存 |



第一、三份接的是已经准备好的控制片，不会把任意RGB自动识别为真实深度/骨架。普通源片需要对应预处理器；已有Blender准确深度/关节投影时优先直接提供，不重复做单目估计。第二份可直接接普通RGB自动提取边缘。工作流输入选择可替换，验证人偶/庭院不是硬编码规则。



使用顺序：打开相应画布 → 在输入视频节点选择/上传本镜素材 → 核对统一宽/高/帧数和时间窗 → 修改镜头描述/种子 → Queue并等待 → 看实际控制预览和生成片，局部重绘同时比较原始片/保护片。示例名以`示例_结构控制_`开头，已放在原生input选择器可见位置。第一次安装后旧界面若报模型缺失，刷新浏览器再选，不重复下载。控制片、源片、蒙版不能选成同一个文件来敷衍所需职责。



作者共支持 Canny、Depth、HED、MLSD、Pose、Scribble、Layout、Gray 八类和inpainting。其他类型可按相同入口替换规范控制视频，但未逐类实测的模式不能算验收。Layout使用VACE式白底、稳定颜色编码主体的边界框序列；不是传一段自然语言布局文字。骨架/深度中未编码的信息仍要靠外观图/文字与模型推断。



## 模型与接法



- 本机沿用Ref2VA pruned W6A8、Qwen3-VL32B NVFP4 AWQ、H3 INT8视频VAE与FP32音频VAE。控制权重选官方Comfy-Org的 `minimax_h3_fun_controlnet_union_2.0_pruned_int8_convrot.safetensors`，约4.22GiB，放 `models/model_patches`；不是再下13.5GB级源精度整分支或另一套底模。

- 原生 `Load Model Patch → Apply MiniMax H3 Fun ControlNet` 的MODEL输出必须供实际Guider/采样器；`control_video`接控制帧，不能仅把它放普通参考槽或只挂一份LoRA。外观参考另接 `MiniMaxH3ReferenceToVideo` 的正确图像/视频槽；骨架/深度图不要充当人物外观照片。

- **v2关键差异**：10个控制块、注入层 `[0,5,10,15,20,25,30,35,40,45]`，`control_in_dim=49`，视频蒙版用 `post_norm`，不施加音频控制。Comfy原生按权重/metadata构建；独立VideoX-Fun必须用 `minimax_h3_control_inpaint_post_norm.yaml`，旧5块v1配置会静默漏权重。不能以无报错/出MP4当作配置正确。

- 基准40步、CFG1（BasicGuider单条件）、res_multistep/simple、video/audio shift12/3、控制强度1、区间0–1、24fps、batch1，不叠Turbo/Flex/动作LoRA。40步来自作者演示，res_multistep/simple与本机官方原生模板对齐；量化/剪枝与Comfy调度并非源精度VideoX运行的逐数值复刻。

- 官方模板注明FL2VA/Ref2VA均可承载，但本批优先验证上述Ref2VA路线。不要把两种底模、Turbo、Flex或旧ControlNet版本的所有交叉组合都当成已测。确需加速/专项时使用匹配家族并为受影响组合试片；无需默认叠满所有LoRA。



## 控制片的时间和空间



1. 镜头按独立段准备。源片预先转固定24fps，截成目标时窗；长片不要先整片解码再在图内截取，否则可能占满RAM。

2. 当前示例832×480、124帧（约5.17秒）。H3用 `17n+5` 帧桶；作者训练/展示主要5–15秒。图内三个Int节点统一输出宽/高/帧数，控制/原片/蒙版的支路共用这些值；空间32对齐，蒙版nearest，不靠各支路不同的裁切补齐。不同比例素材应在导入前按需求统一，而不是拉伸关键主体。

3. 原生控制节点会在时长不同时截前帧或保持末帧；这是容错，不是动作自动重定时。用户要慢放/加速时先明确重采样控制片，并同步提示中的动作时点。

4. 视频结构控制不自动保源音轨。当前链由H3生成音频；需要保原声/配音时按同一时窗另行抽取并在后期核对同步，声音不由骨架/深度约束。



## Blender预演到正式镜头



经 `$blender-core` 设置相机、主体动作、空间尺度和接触，再导出：无调试覆盖的RGB预演、固定近远范围的灰度深度或规范姿态序列，以及必要蒙版；保留.blend及实际相机/帧范围。白模不必先生成高精度资产。



RGB普通参考适合传达大意；深度/姿态Fun分支增加逐帧结构依据。Blender深度要近白远黑，整段使用同一距离映射，避免每帧独立归一化造成“呼吸”；不同画面遮挡/新露出区域仍由生成模型补全。需要身份时另供认可的角色图；深度不能编码脸和衣服。



验收必须与控制源对照首中尾及动作关键时点：主体轨迹、相机方向/速度、遮挡、位置/人数、衣服、背景与时序稳定性，而不是只看单帧更漂亮。结构约束仍不是执行器；精确握持、碰撞、产品尺寸或逐像素路径有硬要求时，保留真正CG渲染/合成路线。



## 局部重绘与连续导演台



蒙版白改黑保，`source_video`只在接了mask时参与；同帧原片/蒙版可来自跟踪或Blender物体遮罩。当前模板另存模型原始片，再将生成区域合成回原片以保护黑区。最终MP4是有损编码，不能拿压缩解码后的像素差直接否定/证明张量合成的精确性；需在编码前核对保留区，边界、阴影、反射和运动连续性另看视频。阴影应纳入必要上下文，不沿物体轮廓硬切制造贴片感。



静态外观替换时写整个片段的目标状态，如“从首帧起始终是同一颜色/服装”，并保持运动职责来自源片。仅用“replace/变成”等措辞时，模型可能将编辑理解为片中发生的变化过程。即使补充静态状态，也要检查首帧和全段，不把蒙版外保护通过等同于蒙版内目标全部完成。



这批是原生单镜头控制画布，不是已验证的导演台任意分段控制插件。导演台能接MODEL不代表会为每段自动切正确的控制片时窗；直接将整片控制补丁接多段，可能每段都从控制片开头取帧。长片先按镜头/段落切同步控制片，分别生成并审查接点；确需连续长镜头的逐段控制时，先实现并验证对应时间窗/历史引导，不能默认全局连接已经完成。



CrossView是估计几何→新机位warp→AddGuide＋原片参考的特定LoRA链；本控制分支接的是显式结构视频。二者不互相替代，默认不同时堆叠。SemanticBridge是文字语义软约束，不会代替这些逐帧控制通道。



## 资源、排错与清理



Balanced、一次一个GPU任务，保留RAM/提交保护。新增控制分支会增加显存、RAM、VAE编码和采样耗时；64GiB分页只增加提交余量。先用本批尺寸/帧数测试，不把原版H3历史分辨率外推为ControlNet同尺寸必过。



没有控制效果时依次查：是否真的使用patched MODEL、正确v2文件/10块/post_norm、控制片内容/方向、强度/作用区间、时间窗、输出与控制尺寸。灰度不是伪彩色深度；骨架不保证脸、手指或道具接触。主结构跟随但身份/光影漂移时补外观依据或返工该镜，不以加更多LoRA代替诊断。



运行按 [runtime](runtime.md)，收尾按 [cleanup](cleanup.md)：保留权重、可复用输入、.blend、成品和必要记录；清理完成后无用的逐帧渲染、几何/蒙版转换副本、下载分段与无续作价值的H3缓存，不清空整个原生output或共享模型缓存。

## 本机实际验证（2026-11-02）



同一套可编辑Blender预演、832×480/124帧/24fps/40步。保存工程已独立回读，人物实际平移1.2m、相机横移1.1m，RGB/深度/骨架/蒙版对齐；静止预演的旧尝试不计入下表。文本无控制基线已留作对照，未重复运行。



| 功能 | 实际秒数 | 最低可用RAM GiB | 本例效果与边界 |

|---|---:|---:|---|

| `结构控制/01_深度与白模运镜` | 333.1 | 8.54 | 修正后的动态深度片实际引导了人物右移/抬手及相机横移，主要墙/双柱/箱体布局延续；生成片新增近景石台，柱体及箱体设计被重解释，不能视为精确几何/内容锁定。 |

| `结构控制/02_边缘视频控制` | 345.2 | 8.55 | RGB视频经图内Canny后，人物移动/抬手和镜头横移能跟随，红箱及主要轮廓比无控制基线更接近预演；柱体圆化、比例及墙边构件被重解释/增改，仍非像素级或对象数量完全锁定。 |

| `结构控制/03_姿态视频控制` | 335.1 | 8.57 | 骨架片引导人物在画面中右移、抬手后落下，二维大姿态/节奏可辨；骨架未编码的背景、相机视角和红箱尺寸与白模差别明显，不能用姿态单独锁整场景或手指细节。 |

| `结构控制/04_结构引导视频局部重绘` | 353.5 | 6.97 | 明确全片静态目标后，首中尾及12个抽帧均为黄色木箱，原片人物/相机运动保留；第0/61/123帧编码前蒙版外RGB最大差0。框形蒙版边缘仍有轻微亮度差，应收紧/融合边缘并包含必要阴影上下文；不宣称任意素材一键无缝。 |



四条链均完整解码并对照12个均匀时点；功能可用不等于所有人物细节、背景、数量、物理都符合原片。局部重绘另对第0/61/123帧的编码前保护图测量，黑区RGB最大差为0；这是三帧保护抽检，最终有损MP4不声称逐像素不变。需无损交付时另选合适无损导出链并核对。



本批使用Balanced和实际64GiB分页，保护器本会话未触发中断。显存与物理RAM仍紧于无控制分支，不能外推更高分辨率、15秒、多参考、全部八种控制或与Turbo/Flex/导演台多段的任意叠加都通过。一次一个GPU任务；这些配方已验证，无需为阅读Skill重跑。
