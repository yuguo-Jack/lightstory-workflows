# ComfyUI Local Workflows



按任务选择、维护或运行本机通用工作流：能力补充完成安装与验收，具体内容任务完成实际生成、检查和交付。根据用户已授权的范围执行，不为分步准备请求额外索要确认。



## 独立使用与职责



- **单独调用即可完成模型任务**：一张图、一段或一组视频、GLB/绑定资产、配音或音乐，从选路到实际产物、检查和清理都由本技能负责。用户只需给目标与必要素材，不必先建影片、填写剧本或加载Video/Game总流程。

- **由上层调用时是执行环节**：沿用其项目ID、镜号/资产ID、目录、已选参考和验收要求；完成配方/请求/运行/排错，返回实际产物、检查结果与返工/缓存状态。上层负责剧情、美术取舍、跨镜头剪辑及整片验收；不在这里重设这些决定或再递归启动同一上层流程。

- 完整影片或游戏需求才按需交给对应总入口统筹；所需Blender检查/控制素材可直接调用相关专用技能。单项模型任务不以“还要进入Video/Game”为由留下未完成的生成。最小交接信息见[任务与结果交接](references/runtime.md#任务与结果交接)。



先区分任务类型：**能力补充/通用库维护**包括模型、节点、通用画布安装更新和验收，按模型/功能归入通用栏目，样片仅作验证证据，不另立生成项目；**具体内容生成**才按用户素材、剧本和交付目标组织项目。两类任务都优先复用现有通用画布。生成任务仅换素材、提示词或参数时保存运行副本，不重复新增UI；确需项目特化节点/流程时另存`Projects/<项目ID>/<模型>/<功能>.json`，不覆盖通用画布。详见[画布复用与项目定制](references/runtime.md#画布复用与项目定制)。



## 按任务选择

| 明确需要人物运动/表情、复古动画、主体环绕、卡片、子弹时间或源片换机位 | [H3扩展LoRA](references/h3-extra-loras.md) | 专项均可不加；按作者家族/触发/采样配套选用。CrossView须完整Guide链，ORB环境/动物冻结有已知限制；成人级（NSFW）LoRA按[快速选型](references/h3-extra-loras.md#成人级-nsfw-快速选型)区分运动、细节、输入方式与速度 |
| 原图/白模结构控制、局部重绘、下一镜和链式故事板 | [Qwen扩展](references/qwen-extensions.md)；视频读[H3 Fun控制](references/h3-controlnet.md) | 控制片接结构节点，外观参考另供；Next-Scene是静帧；单镜Fun不等于导演台任意分段自动控制 |

每次实际运行前读 [操作与排错](references/runtime.md)和[空间检查与清理](references/cleanup.md)，记录本次输出、临时目录及缓存归属。查询/准备工具为 [scripts/library.py](scripts/library.py)，使用标准库且不会提交推理；它是便利入口，不限制直接使用本机CLI、系统Python或当前ComfyUI API。各模型参考给出功能与边界，具体模板名及当前验证状态读取实时目录和验收索引；只加载本次相关参考。



## 组合路线



- **角色静态资产**：Qwen `08`清楚正面 → 人工筛查 → Pixal单图1024 → 确需背面时用Qwen `09`补同一主体的背/侧面并比较双/四图 → 合格GLB进入Blender。可编辑静态网格不等于具备合格拓扑、骨骼、蒙皮、表情或布料物理。

- **连续视频**：常规连续镜头选`10`、多分镜选`08/09`；快速探索可选`02/18`或连续Turbo`11`。新增`Pika Flex/06`提供另一套六步连续路线，使用条件和实测边界见[Flex说明](references/h3-pika-flex.md)，不默认替代全部常规任务。动作/运镜LoRA、条件桥、精修/放大`12/13/14`按需选择。可选动作阶段增强使用导演台“分组LoRA”，保持同一底模和段间引导；全局LoraLoader影响所有段。Turbo与Flex都改变采样路线，不视为无损加速；不要将Flex、Turbo和常规的噪声表或缓存混用。搭配、触发词、过渡与缓存边界见[专门说明](references/h3-lora-continuity.md)。旁白/音乐分别走Ming/Music，再后期混音。

- **从剧本到成片**：用户要求整片叙事、镜头编排、剪辑/混音/包装和交付时，由 `$video-production-workflows` 统筹，本技能承接模型任务。只要求一个模型片段或连续生成时，按本次范围独立完成；已经由Video调用时直接交回结果，不再次启动Video。单个MP4的模型验收不自动代表完整影片验收。

- **分镜与白模结构引导**：Qwen Fun先把轮廓/深度作为静帧结构依据，Next-Scene按镜设计候选并筛查；Blender输出的同步深度/姿态/边缘片接H3 Fun原生单镜头链。实际输入、配方和边界见上述扩展参考，不默认与Turbo/Flex或导演台任意多段控制混用。

- **小区域精确保留**：Qwen `04`按蒙版合成保护预处理原图。H3 SemanticBridge是软文字语义增强，动作LoRA是生成倾向，二者不是像素级控制、骨骼动画或碰撞仿真。

- **游戏角色与真正动画**：Pixal静态GLB可按任务接SkinTokens的自动骨架/蒙皮，再由`$blender-core`检查和处理。真人视频动作由Blender入口路由到已安装`blender-motion-capture`，在外部Motion2MixamoRig运行；它不是新增Comfy视频画布。普通人形也可选Mixamo/Rigify。碰撞、角色逻辑、服饰物理与运行端验收继续走Blender/UE。先读[后续选路](references/game-pipeline.md)，不将模型生成成功当成可玩角色。



## 执行顺序



1. 查询实时目录与输入，选满足目标的最小流程；只加载有关模型参考。

2. 检查已有服务、空队列、启动配置、内存余量和素材。当前正式API/画布、节点接口和日志优先于技能快照；先确认配套模型/编码器/VAE、条件输入和实际生效字段，不跨模型照抄采样、触发词或参考标签。

3. 用任务副本替换提示词、图片/音视频、种子和独立输出前缀；有文本条件时充分写清本次内容与风格细节，H3按`$h3-prompt-writing`的对应模式指南编写。准备后做[提示词与实际请求核对](references/runtime.md#提示词与实际请求核对)，确保文字和参考进入有效字段。具体生成任务的项目特化UI按上述Projects栏目另存，能力补充的通用UI按模型/功能归档，不覆盖无关模板。H3还要更新实际生效的时间线分段或外部Group。

4. 用户要求生成时，准备请求后继续POST、等待、检查实际输出；`prepare`不等于任务完成。一次只运行一个GPU任务。提交超时先查现有队列/历史，避免重复任务。

5. 检查用户这次素材的输出，交付可打开文件或有效预览页，并说明所用功能、关键参数、实际效果和限制。不要仅以文件存在或旧样例通过作为验收。

6. 每批/阶段和工作期间按[空间检查与清理](references/cleanup.md)处理，再做交付前收尾：覆盖任务目录、ComfyUI实际临时目录及本任务的原生output中间缓存。保留模型、用户输入、成品和必要返工/续作缓存；明确无用途的大临时文件当轮清理，不只列候选。返回小型运行/清理记录，报告实际回收量和保留用途，不整库清空共享位置。



## 验证边界



库中81份主画布：Qwen17（基础11＋结构/分镜/可选人物6）、Pixal7、H3 46（原24＋Pika Flex6＋专项扩展12＋结构控制4）、Ming5、Music2、SkinTokens4（其中2份CUDA推理、2份CPU处理）。各批次实际API、界面回读、输出和审查按验收索引分别留证；Flex另有常规H3同条件对照，扩展LoRA保留运行、功能与内容约束的分级审查，不把未完成项目算通过。历史通过不代表文件永不清理或新素材自动合格。声音听感、人物细节、拓扑、高动态接触、任意长度衔接仍需按任务审查。不要因调用技能重跑全部验证。



文档/静态检查不新增实测结论，也不触发旧样例回归；新创作按本次授权执行并审查实际成品。



验收索引把“历史成功但旧样片当前不可用”与未测试、版本失配和真实运行失败分开；例如已清理的Pixal角色验证成品，不因缺旧GLB就自动重跑。新任务仍检查自己的实际输出。



安装依赖和API源码不属于缓存；位置见运行参考。可用能力以当前配置、节点和模型检查为准，不把文档提及的可选工具或历史安装自动视为已就绪。
