# Game Art Direction

从用户提供的审美方向建立统一视觉语言，再用真实游戏画面验证。由上游 Art Bible 与游戏资产美术参考适配，[来源和改动](references/sources.md)。这不是一种固定画风，也不接管项目的玩法或生产工具。

## 工作方法

1. 读用户参考、项目brief、视角/镜头、输入和已有合格画面。注明每份参考负责什么、必须保留什么、可改变什么；区分体验气质与具体渲染技术。已明确风格直接深化，缺少关键方向时才给少量有实质区别的备选。
2. 提炼一句可用于判断取舍的视觉身份和必要的支持原则。用[美术分析参考](references/art-direction.md)拆解形体/剪影、明暗、色彩角色、边缘、材质、光线、细节密度、镜头和动作；不用“高质量、电影感”代替具体规则。
3. 将角色、场景、道具、UI、VFX与声音的气质对应到同一目标。可采用有意对比，不要求所有部分材质相同或所有状态换色。明确关键单位、敌友、交互物和危险信息怎样保持辨识。
4. 在既定引擎的代表性镜头建立视觉切片：主体、环境、接触处、特效与少量HUD一起看。概念图可由本机Qwen等辅助；Blender负责需要的几何/材质/渲染，运行端验证真实灯光、色彩管理和动态结果。不能用一张精美生图代替实机目标。
5. 以原生显示尺寸、工作放大尺寸和实际运动情境检查。比较剪影、明暗层次和色彩，再看细节；覆盖代表性背景、距离和明暗变化。差异要定位到具体维度，每轮优先修最影响一致性的部分。
6. 将可复用规范写入项目的Art Bible/等价记录，再批量制作；必要时用[美术方向简报](assets/art-direction-brief.md)。登记正式参考、变体规则、目标镜头、合格/不合格例子及资产预算，之后每批按同一条件复核。

## 与制作总流程衔接

- 在 [Game Production Workflows](../game-production-workflows/SKILL.md) 的概念/灰盒与垂直切片阶段按需使用。局部风格返工沿用已有规范，不重新立项或重做全部章节。
- 玩法与语义取舍配合 [Game Design Theory](../game-design-theory/SKILL.md)；HUD/菜单实际行为与交互配合 [Game UI Design](../game-ui-design/SKILL.md)。
- 正式资产按总流程分工：ComfyUI生成与编辑、Blender清理/材质/动画、UE实时表现或Game Studio的Web实现。不另行安装整套工作室协调框架，也不要求固定多Agent或逐节写入审批。
- 用户已经选择的比例、颜色、光影和风格优先。不要将某次角色、黄昏/长阴影、写实/卡通偏好固化为通用规则。技术限制影响既定方向时给出可审阅取舍，不默默降质或换风格。

## 交付与限制

输出能指导下一批资产的视觉规则及代表性实机证据；未完成运行检查时标明只是视觉提案。视觉一致性仍需要评审，不承诺写了prompt或固定seed就能消除生成漂移。参考图用于分析，不自动获得其内容分发权；对下载素材和字体按现有资产许可流程登记。

分析请求交付方向与实施建议；已授权制作则继续完成切片、对照、修复和项目记录。全局Skill仅保存通用方法，风格prompt、角色ID与生成缓存留具体项目。
