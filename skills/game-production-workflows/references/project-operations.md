# 项目运行、续作与收尾

## 收纳与当前事实

优先沿用用户已有结构。新项目可用下列布局，按规模减少，不预建一堆空文件：

```text
project/
  docs/                  创作简报、决定、使用说明
  production/            当前状态、资产记录、需求/验收矩阵
  references/            用户样例及其职责/来源
  art/source/            保留的高模、Blender源文件、生成原稿
  art/export/<target>/   所选目标的合格导出与贴图，需要时区分web/ue
  audio/                 成品配音、配乐、音效及需返工源
  game/                  所选运行工程：UE工程或Game Studio的Web代码/资源
  scripts/               本项目的制作/导入/构建工具
  workflows/comfyui/     画布索引、定制版API及运行请求；UI画布存ComfyUI原生项目栏目
  tests/evidence/        实际运行、性能、截图与问题复现
  builds/                当前和必要可回退的可玩构建
  cache/                 可重建中间产物，按阶段/任务收纳
```

项目状态只存执行所需事实：阶段、范围/假设、当前构建、已确定决定、未通过项、素材/工程位置、运行中的任务ID和下一步。新会话先读这些信息和相关证据，不重跑全部旧验证。

为跨会话保留主观要求，使用 `creative_context` 或已有文档索引指向当前简报、玩法规格、美术规范、UI规格及参考清单；只登记实际存在的材料，未需要的项保留空值，多个职责可合并在一份文档。暂存附件若会失效，保存到项目稳定位置或登记可访问来源，不为引用而复制整套大目录。需求/风格变更写明用户决定、受影响内容和待复核项，不能仅留在聊天中。

同时记录运行路线、框架/引擎、执行技能及素材分工。Web接管继续用同一状态与资产ID；同一资产可有共享源与目标派生，不能把Web和UE目录各自维护成互不关联的重复母版。未选定另一目标时不创建其空工程或全部导出。

来源/导出/引擎资源的映射保留稳定 ID。重导入维护同一个引擎资源的引用；不靠频繁复制整项目和自动数字后缀维持版本。

## ComfyUI 画布复用与项目定制

1. **先复用，按需要才改流程。** 调用`$comfyui-local-workflows`查询当前通用画布和真实接口。仅需替换输入、提示词、种子、尺寸、时长或已有可调参数时，沿用现有流程，项目内保存本次配置/API请求；不为每个资产或试跑在ComfyUI新增一份画布。
2. **确需定制时从现有画布派生。** 需要不同节点连接、条件组合或处理阶段时，选最接近的通用画布另存，记录必要差异，保持所用模型、采样和输入接口配套。不覆盖模型分类下的通用模板，也不从零重搭已有可用部分。
3. **定制UI统一放原生项目栏目。** 先核对当前实例、用户及工作流根目录；本机当前默认根目录为`${COMFYUI_ROOT}/user/default/workflows`。其下按`Projects/<项目ID>/<模型>/<功能>.json`组织，项目ID与项目记录一致且不与其他项目重名；画布名描述功能和必要差异。目录按实际需要创建，供用户在ComfyUI工作流浏览器直接打开、区分和后续清理。游戏中的视频子任务沿用同一项目ID，不按技能、镜头或每次运行另建项目根目录。
4. **UI与执行请求一致。** 项目`workflows/comfyui/`保存对应API及索引，关联原通用画布、修改原因/内容、原生UI路径、输入/输出/缓存归属和验收状态。API JSON不能代替可编辑UI画布；定制完成要在ComfyUI中检查加载、接线和实际生效输入，用本次代表素材验证受影响流程。执行成功与资产质量分别审查，不因新建项目重跑整个通用库。
5. **按项目管理版本与清理。** 复用同一拓扑时更新参数/运行记录，不无限堆叠同功能完整画布。保留当前可用定制UI、匹配API和必要依赖；它们是项目源文件，不按临时缓存默认删除。废弃版本及大缓存按本项目清理规则处理；以后清除项目画布时，只操作核对归属的`Projects/<项目ID>`范围，不连带删除通用画布、模型、成品或其他项目。

## 子任务执行与结果回接

调用设计、ComfyUI、Blender、Video或运行端技能时，共用项目ID、已有工程、资产/需求ID、已选版本和质量依据。给出本轮目标与保留项、实际素材及职责、用途/镜头/尺度、目标端规格和预算、请求/结果位置及后续消费者；只传本轮需要的内容，不让执行者重置玩法/风格或建立第二个项目。

| 子任务 | 返回后由游戏流程继续做什么 |
|---|---|
| 玩法、美术、UI设计 | 将规则假设、规范和状态/输入要求写回当前项目，安排灰盒/视觉切片/操作验证；具体创作交接见[设计模块](design-and-art.md#子技能调用与结果回接) |
| ComfyUI模型任务 | 读取执行者返回的实际产物、有效请求、检查和限制，登记为资产候选，安排Blender处理或运行端接入；最小模型交接只维护在[Comfy运行参考](../../comfyui-local-workflows/references/runtime.md#任务与结果交接)，参数和模型注意事项不在本总流程复制 |
| Blender制作/动作/导出 | 收回可编辑源、导出文件、尺度/轴心/材质/骨架等必要信息、资产QA和视觉检查及未解决项，再实际导入目标运行端；不把脚本文本或源文件打开成功算交付 |
| Video整段制作 | 按[媒体回接](presentation.md#游戏视频与动效的制作和回接)取得可用成片/图集、元数据和必要源文件，再验证游戏内播放/循环/跳过/状态恢复 |
| Game Studio或Unreal实施 | 收回实际代码/资源修改、构建/运行证据、功能与性能结果、尚存问题和下一步；由总入口核对整条玩家路径和约定内容 |

结果至少关联实际文件/工程对象、来源与版本、状态/证据、内容偏差、下一环节所需信息和缓存保留用途。小任务可共用一份状态/资产记录；项目模板的`execution_records`/`integration_records`是可选索引，不是必须另建一套API或报告。按任务规模裁剪。

分别记录执行、单项素材和目标运行端检查；一个`passed`不能传递成所有层均已通过。已有失败/未测项保留真实状态；只处理受影响依赖，不因换会话或进入下一阶段重生全部素材。模型任务使用项目内请求位置和独立原生输出前缀，正式媒体可用索引引用，不为统一目录再复制一整份。

本入口协调全项目资源和缓存消费者，各执行技能按自己的规则运行和清理。等待、取消或恢复时核对本任务ID，保留已完成结果和断点，不中断其他项目；具体服务/内存恢复由对应执行技能处理。

## 版本与恢复

按实际项目使用 Git，二进制 `.uasset/.umap/.blend` 等按需要用 Git LFS 管理；不把共享模型权重、DerivedDataCache、临时构建和巨型生成缓存纳入源码。检查 LFS 的实际文件与指针，备份不只是一个不能取回内容的指针文件。

在批量资源修改、绑定/拓扑改变、升级、迁移或不可轻易撤销的操作前有可恢复点。保留 Config/Content/Source 和自建插件的来源；预编译插件的 Binaries 可能是必需输入，不能用通用清理规则删掉。

用户已有工作和其他任务不被覆盖。UE 编辑器未保存状态、后台 Blender 副本、ComfyUI 正式模板是不同对象。保持路径/当前项目清楚，不强行停止共享服务、清空用户队列或关闭其他软件。

## 执行与授权

用户授权制作后推进必要的普通本地编辑、生成、导入、保存和验证，不拆成每条命令的确认流程。遇到真实范围/主观决定或新增外部费用时准备具体方案再询问。既有授权持续有效。

用户接受 Mixamo 的路线可用于当前指定素材；不自动换成 Tripo/Leonardo 等付费平台。SkinTokens等已部署工具按现有执行Skill选用，无需重复安装；不因使用方法论自动安装StableGen、UniRig或新的生成权重。新增必要工具的版本/空间/兼容性先核对，按任务范围处理。

本机账号/凭据只由相应应用或受控环境处理；不导出浏览器登录资料。Playwright 使用用户既定的可见持久配置，能复用就不新开并发会话。

## 资源管理

单个重 GPU 阶段串行。ComfyUI 模型阶段结束后按现有技能释放模型，并检查物理内存/提交/显存；共享后端或映射文件仍在使用时不得删除。UE 测性能与资产生成分开。

缓存标明所属任务、是否仍引用、能否重建、返工用途。保存生成请求/种子/工作流版本等小型记录，避免为可复现性保留每次失败的大文件。

## 制作期间的定期空间管理

用户已授权制作期间及时清理确认不再使用的临时大文件。由执行者在工作期间完成检查和清理，Game Studio/Web、UE及本地资产流程统一执行；本规则不自动安装后台清理器或创建定时删除任务。

### 检查时点与预算

- 开始/恢复时记录各相关磁盘可用空间、项目临时目录、当前生成/渲染/构建缓存及归属。优先按登记路径检查，避免每次检查都遍历整盘/共享模型库。
- 每批资产生成、重拓扑/烘焙、渲染/模拟、导入、构建/打包或阶段验收后，先检查结果，再清理明确废弃的大中间数据，然后进入下一批。失败/中断后保存小型诊断摘要并盘点残留。
- 连续工作至少每2小时检查一次；活动任务可以只测空间，旧数据只有能证明隔离且无人使用时才清。长任务通过可恢复的查询/轮询插入检查；暂时无法检查的工具调用返回后立即补查。不为清理打断活动构建、GPU任务或用户进程。
- 默认预警：已登记临时数据较上次检查增长30 GiB，或合计超过60 GiB，或任一相关盘可用空间低于60 GiB，任一触发就提前盘点/处理。新增大生成/烘焙/构建前预估额外磁盘峰值，至少另留10GiB余量；不足时先处理再提交。
- 这些数值触发盘点，不要求一定清理或把占用降回阈值以内。确认增长来自必要素材、活动任务、工程依赖或返工数据时可以全部保留，记录用途并将本轮标为“无需清理”。实际剩余空间足以容纳后续写入峰值和余量时继续工作，无需因预警暂停、改批量或降品质；只有实际容量不足时才调整批量/存储安排。模型、源资产、UE Content、必要`.blend`、代码、有效构建不按“无用临时文件”删除；运行中/待返工缓存超预算也不能删。
- 阶段结束、工作停止、暂停/交接前再查；跨会话读上次检查时间、保留项/用途和结束条件，不把旧中间数据当作无人管理的永久积累。

### 当轮清理与控制版本数量

大文件按活动任务、正式依赖、必要返工、已废弃、归属不明分类。确认无用者当轮执行清理，不只列候选；需要保留者记录路径/大小、依赖对象、用途和复查/结束条件。不要把“可能以后有用”作为保留所有试跑的唯一理由。

优先处理废弃生成/导出、同一资产的无用途完整副本、重烘后的旧中间贴图/投影视图、失败不再恢复的映射文件、无用途渲染帧和模拟缓存、已作废构建的staging/解压/安装包。当前可用构建及确有必要的回退版本保留，避免每次测试都永久保存整份重复工程和构建。

Web的当前production build、项目依赖及仍引用的媒体不删；旧失败构建、临时打包副本、过期自动化截图/录像按用途处理。`node_modules`、npm工具缓存及共享工具不是默认每轮清空的任务临时文件。UE的DDC/着色器/编译缓存单独记录其增长与用途；过大时识别废弃版本和受支持处理方式，不能把整个共享缓存或Intermediate/Binaries/Saved盲目删除。

检查范围覆盖项目`cache`、本次ComfyUI原生input/output/temp/H3段缓存、Blender渲染/烘焙/模拟残留，以及当前游戏构建/自动化测试所产生的临时路径。按下文对原生目录、预编译插件、存档、自动保存及当前日志的保护执行。

在项目状态`cleanup`或现有等价记录里写检查时间、各盘可用空间、临时大小/增量、候选/删除/保留项和下一次检查。清后复查当前构建与工程依赖，记录实际观测空闲变化；不把硬链接文件长度合计当真实释放量。普通周期清理不另做整目录大备份。

安全回收后仍空间不足时，先不启动下一批大写入，可继续其他独立实现；报告实际大占用和必要保留项再确定安排。锁定、只读或策略拒绝按下文处理，不强制、不换壳绕过。

## 收尾清理覆盖两个区域

下列分类与保护同时适用于制作期间的每一轮周期清理；交付时再完成最终检查，不等整个项目结束才处理无用大文件。

**项目工作目录**：清理已无用途的失败输出、重复下载/解压、旧渲染帧、已合并分段、自动化临时场景、过时打包 staging 和不再返工的中间缓存。保留一个规范高模/源纹理用于重烘，不保留每个阶段完整重复副本。

**工具原生目录**：追踪本次 ComfyUI input/output/temp 和 H3 分段缓存；当前任务需返工就保留，不再使用的大临时文件按 ComfyUI cleanup 处理。Blender 材质可能仍引用投影视图；先烘焙、打包/改成稳定路径，检查依赖，再删中间图。

UE 的 DerivedDataCache 是可复用缓存，不默认每次清空。Intermediate、Binaries、Saved 等不得整目录套规则删除：分辨项目可重建产物、预编译插件、存档、配置、自动保存、当前日志/崩溃证据。释放空间与下次编译代价一起说明。

先核对当前进程、文件依赖、解析后的绝对路径及链接。只清理本次已授权且确定无用的对象，从不带强制选项的原生命令开始；不使用 `-Force` 绕过锁或策略，也不更改属性/换壳绕过拒绝。被拦截时保留记录并给用户明确目标/原因和可审阅命令。

统计清理前后实际可用空间；文件长度合计不等于硬链接/缓存释放的实际空间。不删除用户原图、模型权重、源工程、成品、必要证据和其他项目文件。完成后记录剩余大文件的用途，避免只列候选却不处理确定无用的大文件。

来源：[Git LFS](https://git-lfs.com/)、[UE Derived Data Cache](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-derived-data-cache-in-unreal-engine)。本机 ComfyUI cleanup 是原生目录处理的详细入口。
