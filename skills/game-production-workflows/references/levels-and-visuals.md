# 关卡、场景与视觉质量

## 灰盒先验证空间

先用真实角色高度、移动速度、交互距离、门/台阶/坡度和镜头测试布局。关卡要支撑玩家的目标与路径，而不是先铺满漂亮资产。检查可达性、重要目标的视线、遇敌/解谜节奏、回退与重试点；非战斗项目使用自己的行为场景。

内容较多时，按[玩法模块的内容与节奏检查](../../game-design-theory/references/design-methods.md#内容关卡叙事与教学)把目标、信息/线索、行动空间、挑战/休整、分支与恢复安排成可玩的片段；任务/对白的条件和结果接入真实状态。程序生成需检查不可达、无解和随机种子复现，不能只证明场景能生成。

模块化构件遵守统一网格、尺度、轴心、接缝和材质规则。重复自然物优先实例化/变体，避免每棵树都独立生成。Terrain/Landscape、PCG、World Partition/HLOD 按场景规模选用；小关卡不需要先搭开放世界技术栈。

## 让画面在游戏中成立

视觉目标未定或资产风格漂移时，调用 [Game Art Direction](../../game-art-direction/SKILL.md)；沿用项目已确定的美术规范和代表性目标，不重复重定风格。下述检查应用于所选UE/Web运行端；Lumen、Nanite、Paper2D等是UE专项能力。

- 以用户参考确定主光、天光、曝光、色彩管理和材质响应，先用一套代表性区域校准，再扩展。不要把固定黄昏、长阴影或过度电影调色当默认美术方向。
- 材质和细节尺度要符合建筑、人物与道具比例。接触处的几何与阴影一致；地面/水/岩石等交界由真实空间关系支撑，不能仅把缝画进纹理。
- 反射、透明、皮肤、头发、薄片和植被需要在目标距离/角度测试。强景深、运动模糊和锐化不能遮掩不清晰单位或错误表面。
- Lumen、Nanite、虚拟阴影、后处理和高分辨率按实际目标与版本选择，分别测收益和成本；不默认全开，也不假设某项技术自动解决材质、透明或骨骼负担。
- 比较静止、移动、转向、曝光变化和遮挡。高质量需要稳定的动态结果，不只是挑一张静帧。

## 视觉特效与可交互场景

Niagara/材质/灯光/声音与真实事件连接：命中位置/法线、表面材质、物体速度、状态变化。检查重复触发、错位置、粒子遮挡目标、过度透明叠加和音画不同步。

爆炸、火焰、烟尘、破碎和水花按玩法表现选择，不要求每项都做全物理模拟。可破坏状态要有碰撞、导航、存档和重置逻辑；一段爆炸视频不能代替能交互的物体。

俯视场景检查密集单位、血条、选框、路径指示、遮挡轮廓和 UI 层级。第一人称检查近景道具与粒子过屏；第三人称检查角色轮廓、相机遮挡与动作可读性。

## 原生 2D/2.5D 分支

使用 Paper2D 的 Sprite/Flipbook 等合适能力与 UE 的碰撞、UI 和关卡。按项目选择：Qwen 生成并规范化的精灵、Blender 动画多角度渲染、或三维场景配合2D角色。不因原生目标就强迫所有东西变成实时高模。

精灵需统一帧尺寸、基线/脚底、枢轴、动作轮廓、透明边缘与光线；逐帧生成可能身份漂移，需要筛查或基于同一模型渲染。像素风和高清插画分别选择滤波、mip、抗锯齿与相机规则，不全局关闭所有图像处理。

图块接缝、前后遮挡、平台/单位碰撞、屏幕缩放及 HUD 在实际分辨率检查。复杂2D骨骼动画等若超出现有工具，先评估原生替代和插件需求，不悄悄购买第三方或改成网页实现。

二维/2.5D角色按玩法约束运动平面，校准碰撞厚度和深度排序；视觉上处于前后层的物体，不应因不合理三维碰撞阻断角色。
