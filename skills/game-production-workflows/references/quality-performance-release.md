# 质量、性能、测试与交付

## 为“高质量”建立可以执行的标准

从用户参考和范围确定目标，而不是写“AAA/电影级”后默认达标。按最终镜头、实际显示尺寸、目标硬件与构建设置检查：

| 维度 | 需要的检查 | 常见误判 |
|---|---|---|
| 功能完整 | 用户能完成约定循环，成功/失败/重试/退出与恢复真实有效 | 能走动的展示场景当完整游戏 |
| 输入/镜头 | 响应、焦点、边界、避障、不同帧率与输入设备 | 只看静帧或键盘演示 |
| 几何/材质 | 多角度/距离、法线、UV、纹理接缝、尺度及光照响应 | 4K贴图或高面数自动等于精细 |
| 角色/交互 | 动作过渡、足手接触、衣物、拾放、碰撞和状态恢复 | 动画播放成功当作交互正确 |
| 视觉/听觉 | 与选定参考一致、目标清楚、UI可读、反馈同步 | 后处理更强就算提升 |
| 性能/稳定 | 目标机帧时间、内存、显存、加载、长时间与重复操作 | 编辑器平均 FPS 代表正式构建 |
| 成品 | 独立启动、关卡/资源齐全、设置与存档、说明和已知问题 | 编辑器能运行就算打包验收 |

客观缺陷自主修复；主观表现给用户代表性实机截图/短录像/可玩构建评审。不能把自动比较分数当作审美结论。

玩法验收回查 `game-design-theory` 在项目留下的设计假设和试玩观察；视觉验收对照 `game-art-direction` 的正式参考与目标镜头；UI验收按 `game-ui-design` 的屏幕/状态和输入路径运行。分别记录实现通过、体验待评审和用户已认可，不能把“设计模块已执行”算作三者都通过。

手感验收按[同条件对照与恢复检查](game-feel.md#验收)，核对控制、接触、反馈时序与密集事件，主观取舍单独评审。在线项目执行[联机验收矩阵](multiplayer.md#联机验收矩阵)，将拓扑、实例/角色、人数、网络条件及各端结果关联到当前构建；同步、恢复和性能检查按变更范围继续回归。

## 测试分层

下列UE工具与PIE/原生打包步骤适用于Unreal分支。Web由`game-studio:game-playtest`及当前Web专项技能执行：代码/资源检查 → 开发运行 → production build → 目标浏览器实际游玩。检查加载/资源路径、输入/焦点、布局、音频启动、存档/恢复、重开及性能；不以开发页截图、HTTP成功或build成功代替完整核心路径。详见[路线验收](runtime-selection.md)。

1. **静态/资源**：数据与路径、蓝图编译、导入设置、缺失引用、资产结构。
2. **Blender/文件回读**：几何、UV、权重、动作、导出数量与尺寸。
3. **UE 编辑器与 PIE**：正确出生/控制、场景、动画、交互、AI、UI、存档。
4. **独立/打包运行**：关闭编辑器也能启动并完成流程，资源/插件/设置/路径正确。
5. **玩家验收**：玩法可理解、操控舒适、审美接近目标，记录具体反馈。

按项目选择 Automation/Functional Tests/Gauntlet 或小型可复现测试场景。不要为了形式给每个可逆美术调整写镜像单元测试；对状态逻辑、存档迁移、确定性规则和易回归问题写有意义检查。浏览器 Playwright 不能代替 native UE 游戏测试。

证据关联需求/资产ID、实际版本/构建、输入、场景、设置及预期/实际结果。重新导入或改变依赖后按[改版影响](asset-production.md#批量生产与改版影响)复核，不能用旧构建截图证明新版通过。运行成功、素材审查、集成和玩家评审分别记录；确实未能测试的目标保留未测，不用本机Windows结果外推其他设备/平台。

覆盖适用的异常：无存档/旧存档、重复拾取/释放、目标已删除、路径不可达、暂停切换、重开关卡、窗口失焦、分辨率/设备变化、完成后继续输入。联机异常沿上述矩阵验证；程序生成和大规模群体按各自特有状态补充。

## 性能闭环

先记录目标分辨率、帧率、画质/上采样、场景、构建配置、GPU/驱动和后台负载。60 FPS 的一帧约16.7ms、30 FPS约33.3ms是预算换算，不是本机达标结论。

使用当前引擎的 stat、GPU profiling、Unreal Insights 等确认 CPU game/render、GPU、IO/加载和内存的瓶颈，再优化；保存同场景前后记录和可重现步骤。单帧截图或一次平均值不能证明整体更快，冷启动和稳定运行也要区分。

记录采样区间和关键场景的帧时间分布/卡顿，而不只平均FPS；检查冷启动、切关卡/流送、密集交互及重复进入后的内存。先区分编辑器/首次编译影响和正式构建的持续问题，再优化。Web按对应运行时工具测同等目标，不直接套UE命令。

- GPU：先查分辨率、阴影/反射、透明叠加、灯光、材质成本和纹理驻留；按证据调整。
- CPU：查 Tick/轮询、AI/导航、动画更新、物理和对象生成；按距离/可见性/状态降低无用工作。
- 几何/场景：LOD/HLOD、实例化、剔除、碰撞复杂度与数据流送；保留主角和关键交互的可见质量。
- 内存/加载：检查纹理分辨率、重复资源、异步加载、音视频和运行时缓存。不能用分页掩盖泄漏，也不只靠把所有内容降到最低。

性能测量不与 ComfyUI 推理、Cycles 或无关重编译并发；用户其他程序可能影响结果时记录，不擅自关闭其工作。

## 打包与发布

Web使用已选框架的正式构建、静态资源/路由配置和目标浏览器验收，保留代码、必要素材、构建与运行说明；对外部署仍按用户授权。以下RunUAT、Development/Shipping和原生依赖检查仅用于UE项目，不是Web交付要求。

尽早测试 Development 构建，交付按目标选择 Shipping；通过当前引擎支持的 RunUAT/Project Launcher 等路径构建、cook、stage、package。参数和平台 SDK 按本机版本查证，不照搬旧引擎命令。

检查启动地图、GameMode、需要的关卡/资产、运行时插件、依赖库、字体/中文、相对路径、读写权限、音频/视频、输入、设置/存档与退出。至少从一个新的启动过程完成代表性核心路径；仅存在 `.exe` 不算通过。

从实际交付目录启动，验证不依赖编辑器、开发工作目录、绝对素材路径或未随包的资源；Web验证正式资源路径、加载和浏览器行为。签名、平台SDK、商店或其他设备未具备验证条件时，说明尚未完成的具体项，不将源工程可用写成所有平台均可交付。

用途和许可在选资产/模型时就记录，发布前再复核实际交付集合。模型及社区转换的具体授权来源/限制按对应执行Skill和随版本保存的许可确认，不在本总流程写成永久不变的结论。存在研究/非商业等限制且不满足项目用途时，先取得适当授权或选可用替代，不能等批量生产后再处理。动作、字体、HDRI、音频、素材和第三方组件同样按实际版本记录，不笼统认为免费或本地可运行就可任意分发。

交付包括可启动构建、必要源工程、操作/安装说明、可调设置、已知问题、真实测试范围和返工入口。商店上传、公开发布和收费购买不由本技能默认执行。更新保留可用旧构建，按需要测试旧存档与重导入兼容。
