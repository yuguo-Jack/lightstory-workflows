# 先选运行路线，再分配制作职责

已有项目先沿用其引擎、结构和可用成果；用户指定Web/Unreal/其他引擎时尊重选择。无明确选择时，根据交付入口、内容规模、目标设备、表现/交互要求和维护成本作判断，记录理由并继续，不必每个项目额外开一次选型审批。

## 选择依据

| 情况 | 通常合适的路线 | 核对重点 |
|---|---|---|
| 链接即玩、免安装、嵌入网页、快速试验，内容与表现预算适合浏览器 | Web → Game Studio | 首屏下载/加载、目标浏览器/设备、输入、声音启动和资源预算 |
| 2D/俯视/横版/网格规则为主，希望快速实现浏览器版本 | Web → Game Studio 的Phaser分支 | 用户确实接受浏览器交付，素材/分辨率/动画及玩法规模适合；不能只凭2D自动选Web |
| 需要浏览器3D，场景和资源规模可控 | Game Studio → Three.js或React Three Fiber | 实际渲染/物理/动画需求、下载体积与运行预算；React已有工程才优先相关分支 |
| 原生安装交付、复杂角色动画/物理/布料、较重场景/灯光表现及引擎制作工具 | 本机Unreal路线 | 目标平台/硬件、原生构建、所需插件和可重复生产能力 |
| 用户要求明显高于当前Web方案的成品表现或已有UE工程 | Unreal优先 | 在代表性实机场景建立品质和性能，不用引擎名字代替证据 |
| 两条路线都可能合适，关键能力尚不确定 | 选最可能成立的一条做小型风险试验 | 验证主要瓶颈即可；不默认同时开发两个完整版本 |

Web可以有高品质美术、物理和完整游戏；Unreal也不保证自动高品质。小规模/要求较轻只是Web候选信号，还要看分发和体验；第一/第三人称或上帝视角均不是单独的选型依据。

记录：所选运行时/框架与版本、目标平台/设备、理由、预算/关键风险、备选方案、触发重新评估的条件、交付及测试方式。用户已明确高品质原生路线时不为了容易演示擅自改Web。

## Web交给Game Studio接管

读当前已安装 `game-studio:game-studio`，保留一份简报、需求和当前状态，由它分配具体执行技能：

- 架构/模拟状态、输入、存档和资源边界：`game-studio:web-game-foundations`。
- 2D：`game-studio:phaser-2d-game`。
- 普通TypeScript/Vite的3D：`game-studio:three-webgl-game`。
- React宿主3D：`game-studio:react-three-fiber-game`。
- 3D导出/压缩/LOD/浏览器资源：`game-studio:web-3d-asset-pipeline`。
- 精灵条、锚点/尺度规范：`game-studio:sprite-pipeline`。
- UI和试玩：`game-studio:game-ui-frontend`、`game-studio:game-playtest`。

这里“接管”是实际调用Game Studio及其专项技能继续完成Web游戏，不能只读其文档后仍按UE流程推进。它不要求创建新聊天或多个Agent。总入口继续负责目标、素材约定和交付完整性；不要另起一套矛盾计划。

交接至少携带：用户目标与未改动的玩法/审美要求、选路理由、项目/代码位置及现有状态、所选Web框架、输入/存档/性能和交付目标、已有素材清单、尚缺素材与制作分工、当前未通过项及下一步；已有[手感配方](game-feel.md)与适用的[联机契约](multiplayer.md)也随项目传入，不由Web接管重置。同时传递[周期空间管理](project-operations.md)的检查间隔、预警值、临时目录归属、上次检查与保留缓存用途。新项目由Game Studio建立对应Web工程；已有项目按其当前结构继续。Web接管不取消制作期间清理要求。

执行链为：总入口选路 → 调用`game-studio:game-studio` → 相关运行时/UI/资产/试玩技能实施 → 遇到素材需求按约定调用ComfyUI/Blender等 → 将验收素材接回Web工程 → 正式构建和试玩 → 总入口核对整体验收与收尾。接管后不因素材来自本地就绕回UE；原生路线继续走UE执行层。

Game Studio默认浏览器2D使用Phaser；明确3D后再选Three/R3F。只加载有关技能。它的默认生图后端不强制替换本项目已经选定的本机Qwen/Pixal链：实际生成按用户选择执行，可借精灵规范化、资产优化和QA方法。插件脚本是否能直接接当前素材应实际检查，不把调用技能当作所有接口已适配。

## 共享素材与目标端版本

先看[资产分工](asset-production.md)。概念/角色原稿、高模/Blender源、可用PBR、动作源、音频、原始UI美术可按需要复用。源文件一份规范版本，按目标派生，不为每种引擎重复生成主体。

Web派生需核对GLB/glTF、网格/纹理压缩和解码支持、加载体积、骨骼/材质/透明度、LOD与碰撞代理；只选运行时实际支持的压缩，不因插件提到工具就假定本机已安装。UE派生按其导入格式、骨架、法线/通道、材质、碰撞及LOD设置处理。

玩法脚本、UE蓝图/UAsset、DOM/UMG、专有Shader、物理/导航和资源加载不能认为跨端直接兼容。只做用户选定目标的必要版本；未来确需换路线时先评估现有源资产和逻辑可迁移部分，不擅自宣布“一键移植”。

## 路线对应验收

UE：使用工程/PIE及打包版本测试。Web：调用Game Studio试玩，检查真实操作、窗口/输入焦点、布局、加载失败、音频启动、存档/重开、目标浏览器和设备性能，并测试production build；开发页截图和构建成功不代表完成游戏。

纯分析请求只给路线/分工建议，不启动工程或推理。开始实现后沿所选路线持续完成原型、切片、生产、测试及交付；只有实际证据推翻关键假设时才重新评估，并明确对内容、源资产和工期的影响。
