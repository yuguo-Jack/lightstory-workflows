# 联机选路、状态边界与验收

在线项目在概念/可行性阶段进入本分支，灰盒就用多个真实实例验证核心交互。明确单机的项目不引入网络框架；同屏多人先处理多输入、玩家归属和共享/分屏镜头，也不自动需要服务器。

## 早期选路

先从已有需求确定：人数、合作/对抗/回合制、是否即时物理、局域网或互联网、目标平台、是否迟加入/重连、进度归属与持续在线要求，以及可接受的响应、运维和服务成本。未确定但会影响架构的项写明假设与风险；不要把未来可能联机当作自动建设完整后端的理由。

| 路线 | 决策重点与执行 |
|---|---|
| UE在线，玩家主机或独立服务器 | 根据公平性、持续运行、人数和成本选择；由Unreal执行层按当前工程核对所有权、复制、RPC及移动同步，复用合适的引擎机制 |
| Web在线 | Game Studio保留当前Phaser/Three.js/R3F客户端，按规则与部署约束选后端/传输及状态同步；客户端框架本身不等于联机后端 |
| 点对点、平台会话或中继 | 核对谁裁决状态、连接建立、NAT/中继、身份与断线行为；P2P不自动解决作弊、权威或主机退出 |

Rivet等仅是候选实现，选中后才检查当前入口、SDK、示例和许可并补足必要依赖；不把旧`multiplayer-game`目录或任一云服务设成通用必装项。多人逻辑可先本机多实例验证；互联网可达性与部署仍需单独实测，不承诺无需配置或运营成本。新增外部费用/公开部署按本次授权处理。

## 状态与事件契约

沿用项目现有brief/技术记录，写清关键状态的稳定ID、修改者、接收者、同步/恢复方式及必要频率。以下按适用项裁剪，不要求另建固定格式的规格文件。

| 内容 | 需要明确的边界 |
|---|---|
| 移动、瞄准、命令 | 谁提交输入、谁验证/裁决；是否需要预测、插值与校正；按游戏类型决定，不默认全部回滚 |
| 生命、物品、资源、任务与胜负 | 权威侧校验条件并提交结果；重复请求、竞争拾取和超时重试不能多次生效 |
| 持物、投掷、门与物理物体 | 所有权/附着/释放/碰撞状态如何转换及恢复；区分玩法物理与本地装饰布料/特效 |
| 动画、音效、VFX与UI | 谁应观察事件、谁只看自己的信息；状态可恢复，瞬时事件可去重，不靠播放一次特效重建世界 |
| 进度、重连与秘密信息 | 房间/玩家/世界各保存什么；晚加入的状态基线与后续更新；仅发送玩家有权看到的数据 |

服务端/所选权威侧验证请求权限、范围、速度/频率、冷却和资源，不信任客户端宣称“已命中/已获得物品”。消息设计区分需要最终到达的关键结果和可被新快照覆盖的高频状态，避免所有对象每帧全量可靠广播。

预测用于改善响应，权威结果仍需收敛；确认、重放和校正使用可识别的事件/动作顺序避免重复结算与重复表现。时间戳、随机性、物理和状态序列按所选同步模式处理，不假定任意引擎物理天然支持确定性锁步。操作反馈与短暂停顿遵从[手感分支](game-feel.md)，不通过冻结整个在线世界改善单个客户端的表现。

迟加入、退出、掉线、重连、房间满/已结束和版本不匹配各有明确结果。需要主机迁移时单独验证；不需要时可清楚结束会话或返回大厅，不能把未实现迁移默认为已支持。断线后的角色/持物/进度归属和恢复时限按玩法决定。

## 执行与阶段交接

UE实际调用现有Unreal技能；Web实际调用Game Studio及当前相关执行技能。传入同一项目、已选拓扑、状态契约、核心交互、恢复要求、目标人数/负载和测试计划。需要身份/匹配/中继/存储服务时只引入明确选中的部分；不另起项目或悄悄换引擎。

先打通“连接/加入 → 互相观察 → 一次共享交互 → 退出/恢复”的最小链，再将同一边界用于资产、动画、UI和关卡生产。UI由`game-ui-design`定义等待/连接/失败/恢复与输入归属，实际状态来自后端；生成资产和视频只提供表现素材，不承担网络权威或会话逻辑。

回接实际客户端/服务端修改与运行方式、版本/配置、拓扑、实例/角色、复现步骤、各端状态与证据、性能和未解决项。公开说明与日志不包含密钥、会话凭据或私人玩家数据；必要小型诊断记录留项目，废弃抓包、长录像和重复构建按原有清理规则处理。

## 联机验收矩阵

| 场景 | 核对结果 |
|---|---|
| 建房/加入/退出、必要的匹配 | 多个独立实例完成完整路径；房间满、已结束或连接失败有可恢复表现 |
| 核心交互与同时操作 | 服务端与各客户端对最终结果一致；拾放、命中、资源消耗或任务推进不重复、不产生幽灵对象 |
| 迟加入与状态恢复 | 能获得当前世界/物品/任务等适用状态，后续事件正确接续，不依赖错过的开场动画 |
| 掉线/重连与主机离开 | 按已定规则清理、保留、恢复或结束；UI和输入可恢复，未实现的迁移准确标注 |
| 延迟、抖动、丢包与校正 | 记录网络设定及实际观察；检查响应、重复反馈、回弹、拒绝请求和恢复，不用本机低延迟结果外推互联网 |
| 所有权与信息隔离 | 非所有者操作被正确处理；他人私有数据/不可见目标不会因广播泄漏 |
| 目标负载与交付版本 | 记录玩家/对象数、各端帧时间、服务器模拟和带宽；实际客户端及所需服务器构建能按交付配置连接 |

UE多玩家PIE适合早期排错，不能代替独立/打包多实例；Web需独立玩家上下文及正式构建。需要互联网交付时再从实际网络验证发现/连接/会话路径。本机单人或单个客户端成功不等于联机通过；不足目标人数/网络/平台的测试保留未测范围，再接回[质量与交付](quality-performance-release.md)。

方法参考与版本核对入口见[来源](sources.md#操作手感与联机参考)，具体API和服务状态由执行层查当前版本。
