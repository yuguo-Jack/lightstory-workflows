# 资产生产：参考到引擎可用文件

## 先定义资产的用途

资产记录至少包含稳定 ID、类型、目标镜头/尺寸、真实尺度、来源、原始输入、源文件、导出文件、材质、动画需要、版本和验证证据。主角近景、背景树木、可拾取物、可破坏物和 UI 图标的标准不同，不给所有资产同一个面数/4K预算。

优先复用用户已有资产、合法动作和可参数化构件。自然/复杂形状可用 Pixal；尺寸精确、需要规则拓扑的墙、门框、楼梯、管道等常适合 Blender 程序化或直接建模。目标是可靠资产，不是最大化 AI 使用比例。

## 路线确定后，先做资产与工具分工

按资产在真实游戏中的用途、镜头距离、交互/变形要求、数量、重复程度和目标预算决定方法。已有合格资产直接复用，不要求经过所有工具；下面是制作职责划分，不强制多Agent并行。

| 素材/功能 | 通常的主制作方 | 后处理与运行端职责 |
|---|---|---|
| 概念、角色设定、场景风格、图标/插画、纹理图案 | Qwen等已选生图流程 | 编辑/筛查一致性、尺寸/Alpha、去无关背景；UI与动画按实际需要规范化 |
| 不规则静态道具、装饰、复杂自然外形的初稿 | Pixal生成 + Blender后处理 | 检查几何/PBR、清理/减面/UV/烘焙、碰撞/轴心/LOD，再进入目标端验收 |
| 主角、近景人物、可变形服装 | 图像/3D生成可提供起点；Blender负责必要精修 | 关键脸部/关节/拓扑/权重、表情和布料适配不能省；绑定/动作按Mixamo、Rigify及引擎路线分配 |
| 模块化建筑、墙/门/楼梯、尺寸精确道具、规则机械 | Blender直接/程序化建模，或先用引擎灰盒 | 明确尺度、拼接/碰撞、UV/平铺材质；重复件实例化。不要每块墙单独生成不一致模型 |
| 简单原型体、碰撞代理、交互范围 | 目标运行时/编辑器直接制作 | 灰盒保留可玩性和尺寸，达到需要时再换成正式美术 |
| 地形、关卡布局、植被分布、重复场景组合 | UE地形/场景与程序化工具，或所选Web运行时的场景系统 | 外部工具提供必要模型/贴图；遮挡、导航、地面接触、实例化及性能在运行端检查 |
| 运行时材质、水面、灯光/后处理、粒子/VFX | UE材质/Niagara/灯光或Web实际渲染系统 | Qwen/Blender可提供贴图和元素；不要用一张漂亮图替代有交互的水面/效果 |
| 骨架/蒙皮与动作源 | Mixamo、Blender/Rigify，自动绑定可选Comfy/SkinTokens；真人动作按需经Blender入口 | 按[角色路线](character-animation.md)选择并查专用技能；Blender修变形/足手接触，目标运行端接状态与交互。生成视频不等于骨骼动作 |
| 游戏UI/菜单/HUD及动画反馈 | UE UMG或Game Studio的Web UI/运行时 | 生图可提供视觉元素，文本/布局/响应/输入/状态由界面系统实现 |
| 配音、配乐、可用音效与过场 | Ming/Music/H3、用户素材及必要声音制作 | 目标端负责触发、空间音频、混音、字幕同步和播放/流送；视频不能替代可玩的逻辑 |

例如一扇可开关的门：规则门框/门板适合Blender或UE灰盒/建模；生成模型可做风格参考或纹理；门轴、碰撞、声音、锁定/开关逻辑在目标运行时完成。漂亮的带门模型并不自带这些行为。

每项记录：采用方法与理由、主制作工具、后处理、依赖资产/版本、源文件、目标端导出、预算和验收方式。分工允许生成→Blender→引擎，也允许Blender直接完成或引擎内完成；不要为流程形式重复导出/生成。

## 共用源资产，按目标派生

概念图、高模、`.blend`、合格PBR、原始动作、配音和音乐可以按需共用。用稳定ID关联源与派生，Web/UE分别输出其预算和格式需要的版本；不为“将来可能换端”预先制作所有版本。

- Web：Game Studio接过运行时后，可调用本地资产流程，再用其`web-3d-asset-pipeline`或`sprite-pipeline`规范运行素材。GLB/glTF、压缩、加载体积、骨骼/透明/材质支持在实际浏览器检查，不能直接塞原始高模。
- UE：按实际项目处理网格/骨架导入、材质通道、碰撞、LOD及运行时设置；引擎专有材质/蓝图不是浏览器可直接加载文件。
- 2D精灵：Qwen可提供基准造型或候选动画条；采用Game Studio的切条、统一尺度/锚点和预览方法时，实际生成工具按当前选择。人物多帧一致性、脚底锚点和动画读感仍须验收，不因已有生图模型就当所有动作条已验证。

资产合格要在**所选运行端**的实际镜头、材质、动画、交互与预算下成立。共同来源不等于同一导出文件无需适配就能跨端通用。

## 参考图与模型

1. 用 Qwen 或用户素材建立清楚的主体参考，控制遮挡、全身边界、服装和姿态。建模参考与宣传图分开；夸张透视、景深和复杂背景会增加歧义。
2. 由ComfyUI技能按当前Pixal参考做抠图、居中和输入核对，先试单图，确需背面/结构补充才比较一致双图/四图。精度、生成级别和资源配置从执行参考选择；较高生成级别是质量/资源选项，不是每个资产必须经过的步骤。
3. 导出 GLB/PBR 后在 Blender 审白模和材质：整体轮廓、正背侧、薄件、手指、眼口、穿插、浮片和缺洞。漂亮颜色可能掩盖错误几何。
4. 错误在参考时修参考；局部几何错误优先局部编辑/重建，严重结构错误再重新生成。不要用越来越重的贴图覆盖粘连几何。

多参考图不一致时，不把增加张数当作提高质量。分别检查身份、投影尺度、相机和姿态。2D重绘生成的背面是推测，不是实际扫描。

## 结构受控美术与2D素材

复杂立绘、图标、背景、纹理图案和候选精灵可由Qwen制作或参考编辑；需沿用轮廓/体积时，通过ComfyUI技能读取[Qwen结构控制](../../comfyui-local-workflows/references/qwen-extensions.md)，选择边缘、深度或同坐标蒙版的适用入口。外观参考与结构条件分别登记，生成画面不是可编辑几何或游戏碰撞边界。

游戏实际显示尺寸决定所需细节；统一精灵帧尺寸、脚底/轴心、透明边缘、图集留边和目标端滤波。需要稳定动作时可用同一Blender角色渲染，而非假定独立生成每帧都一致。HUD/按钮可以使用生图美术，准确文字、血条/数值、布局和交互仍用真实界面系统。Web的规范化可交Game Studio对应资产技能，UE按Sprite/Flipbook等实际接入方式检查。

## 高低模、UV、材质和烘焙

- 保留高模/原始纹理作为来源，复制出制作副本；按 `$blender-core` 选择清理、重拓扑、UV、材质、烘焙、优化和导出技能。
- 静态背景可减面；变形角色需要关节和面部的边流，自动四边化不等于动画拓扑。重拓扑/改 UV 后，把高模细节和可用颜色重新烘到低模，不能保留已经错位的旧贴图。
- 用统一尺度、基线、命名、材质槽和纹理密度。图集/平铺/trim sheet 用于重复构件；独立 hero 纹理留给确实可见的细节。按镜头选择分辨率和 LOD，而不是一律高分辨率。
- 检查底色与数据贴图的色彩空间、法线方向/切线、粗糙度/金属度通道、透明度及包装格式。GLB 内嵌 PBR 不代表引擎导入后自动满足所有项目材质约定。
- 旋转灯光检查材质：高光与阴影不应全部画死在底色上。皮肤、布料、油漆金属、玻璃各用合理参数；不能只靠高饱和与强反射显得精细。

## AI 材质编辑的默认路线

现有组合已能处理材质，不必安装 StableGen：

1. 沿用合格的 Pixal PBR；普通颜色、材质参数、磨损与程序纹理由 Blender 原生节点/蒙版处理。
2. 需要生成式图案或局部改画时，渲染已知相机的引导图/蒙版 → 由ComfyUI选择Qwen编辑或Fun结构控制 → 检查位置/内容漂移 → Blender投影或更新UV区域 → 修接缝 → 烘焙。按当前受支持条件准备边缘/深度和同步蒙版；不要把法线图当作已经部署的专用法线控制接口。图像/结构参考不是绝对几何锁定。
3. 小范围改色可以保留原 PBR；改变材质种类时同步重做粗糙度、金属度、法线等。不能将“布变盔甲”的颜色图直接搭配旧布料参数。
4. 任意图像反推 PBR（Marigold/StableDelight）是可选路线；Pixal 已有合格 PBR 时不重复估计，不因本技能自动下载它们。StableGen 也是将多视角编辑自动化的可选工具，出现重复需求再评估。

多视角修补以同一个三维表面和已知相机为基准。背面、遮挡、小缝隙、UV边界和不同距离都需看；一张正面效果图不能证明 360° 一致。材质修补不能补回不存在的手指或正确脸部结构。

## 导入与复查

选静态 GLB/FBX 或骨骼 FBX，按目标项目规则处理单位、朝向、轴心、LOD、碰撞、贴图和骨架。程序化着色器先烘焙为引擎支持的内容。保留稳定导入位置与来源映射，返工用重导入，不反复创建带数字后缀的副本。

Blender检查按`blender-core`路由到`blender-asset-qa`，再回读导出文件，并在所选UE/浏览器运行端检查真实尺寸、材质、法线、碰撞和实际镜头。高面数源模型可能超过QA默认重检查门槛，应按部件或优化副本验证，标清跳过项；不要无条件删除分离部件，它们可能是眼睛、配饰或衣片。

## 批量生产与改版影响

资产清单关联稳定ID、资产版本、依赖版本、执行记录和目标端资源；候选/执行成功、素材合格、运行端通过分别记录。同类资产先确认第二个不同输入也能复用流程，再批量推进；每批实际接入并验收，不先囤积全部未导入高模。成功项继续沿用，仅重试失败或依赖失效项。

| 改变了什么 | 应复核的下游 |
|---|---|
| 身份/造型参考、整体比例 | 受影响图片、3D/材质、角色动作和目标镜头；未变的其他资产不重做 |
| 几何、拓扑、UV | 烘焙/贴图、蒙皮/形态键、LOD、碰撞及导入引用；单纯改色不默认重做全部骨架 |
| 骨架、参考姿势、尺度 | 动作重定向、根位移、握点/socket、Physics Asset/布料碰撞和运行状态 |
| 动作/对白/视频的时长与事件 | 动画事件、命中/释放时点、音效、字幕、过场控制权和循环/接点 |
| 数据结构、状态ID或存档格式 | 引用、任务/UI绑定、旧存档迁移及相关可玩路径 |

把过期证据标明失效范围，用当前资产版本和构建重测受影响项；不以旧版通过证明新版合格。具体任务/结果记录和恢复见[项目运行](project-operations.md#子任务执行与结果回接)。
