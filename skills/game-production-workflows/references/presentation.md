# 音频、演出和界面

## UI/UX 与可理解性

界面规划、信息层级、屏幕/状态流与输入适配调用 [Game UI Design](../../game-ui-design/SKILL.md)，视觉规范沿用项目美术方向；执行继续沿已选路线。Web使用 Game Studio 的 `game-ui-frontend` 与实际运行时，之后用 `game-playtest` 检查；以下UMG/CommonUI属于UE分支。

UI 使用 UE 的 UMG/CommonUI 等适合项目的工具；CommonUI 不是所有小项目都必需。整理主菜单、暂停、设置、HUD、目标/交互提示、失败/完成、载入和错误状态。只实现适用项，但所有可见按钮都要真实有效。

界面遵从用户审美与信息优先级，先在灰盒验证可读性、焦点与操作，再做正式视觉。覆盖目标分辨率、窗口缩放、长文本/中文、手柄/键鼠焦点切换。字号、对比、字幕、颜色之外的状态提示、重绑定、长按/切换和减少晃动按玩家需要考虑；不是只做一张漂亮菜单图。

将“按 E”之类提示与实际输入映射对应，游戏暂停、鼠标捕获和 UI 焦点切换正确。显示资源、背包、进度等时取真实状态；不要用演示数字或静态贴图假装系统已经接通。

## 现有模型怎样用

| 内容 | 本机路线 | 制作后仍需做 |
|---|---|---|
| 配音/音色/情绪 | `$comfyui-local-workflows` → Ming-3.0-TTS | 短句核对、读音/情绪、时长、降噪/电平、字幕与触发逻辑 |
| 配乐/演唱 | 同入口 → MiniMax Music 3 | 挑选、剪辑、循环接点、响度、场景状态切换；不假设无限无缝 |
| 完整过场、风格视频、预渲染动效 | `$video-production-workflows` → 按需组合 Qwen/H3、Blender、声音、剪辑和本机工具 | 按下节交付可用媒体，再在游戏端检查播放、接点、跳过和返回游戏；单项生成可直接用 ComfyUI |
| 程序/交互音效 | UE 音频工具、合法素材、录制/编辑 | 按材质/速度/距离触发、空间化、遮挡、并发限制 |
| 可保持游戏空间一致的演出 | UE Sequencer/Movie Render 或运行时演出 | 摄像机、角色状态、控制权、恢复点及运行成本 |

当前已部署 TTS/Music 不等于具备单独训练的通用音效模型。不要把音乐生成当精确的开门、脚步或枪声生成器；可用程序声音、合法已有音效或根据明确需求另选方案。

## 游戏视频与动效的制作和回接

需要成段影像或预渲染素材时，实际调用已安装的[Video Production Workflows](../../video-production-workflows/SKILL.md)（`$video-production-workflows`），制作完成后回到当前游戏的资产验收和打包流程。无需另建一套游戏立项记录；简单转码、切片或既有素材整理可直接用本机工具完成。

1. **确定用途和表现方式。** 片头片尾、固定过场、菜单循环背景、场景内屏幕、预渲染技能演示等可走视频路线；需要响应玩家、随自由相机改变、参与碰撞或匹配当前装备状态的表现，优先引擎实时演出/VFX。两者也可按片段结合。视频动效若用于游戏效果纹理，按目标选择视频、带透明度序列或 Flipbook 图集，并先验证接入方式。
2. **传入同一项目的约束。** 提供稳定资产 ID、已定角色/服装/场景/风格参考、剧情与时间位置、时长/FPS/分辨率、镜头、声音/字幕、循环或 Alpha 需求，以及进入/退出游戏时应有的画面和状态。记录目标运行端支持的交付格式、尺寸和内存预算；在游戏项目内划定媒体子目录，复用正式源资产和引用，避免重复复制大模型或整个工程。
3. **由视频流程完成制作与审查。** 按需要走视觉开发、分镜/动态分镜、预演或确定性渲染、H3生成、合成、声音、剪辑和导出。需要视频结构/局部控制时由Video路由到Comfy的H3 Fun及Blender控制素材分支，游戏总入口不再复制具体配方；来自UE的演出/渲染由Unreal执行层制作后交媒体。精确沿用角色几何/动作时采用真实渲染或合成；Qwen/H3可制作或辅助风格化影像。生成视频不是骨骼动作、可编辑几何或实时物理。制作期间沿用游戏项目的资源调度与空间管理约定。
4. **交回媒体与使用信息。** 返回已选可播放文件/图集、必要音轨与字幕、可编辑源/重做依据，并登记版本、真实尺寸/FPS/帧数/时长、编码与颜色、Alpha 方式、声音触发点、循环接点和来源。Alpha、循环和帧间稳定要实际检查；无法满足时改用可验证的合成/渲染路线或准确记录限制。
5. **接入游戏并验收。** UE 按目标平台选媒体播放/材质、Niagara 或 Flipbook 等实际支持的路径；Web 按所选运行时的媒体/纹理支持处理。验证首帧加载、同步、暂停/恢复、跳过、重复播放、输入/镜头控制权和返回后的任务/存档状态；声音服从游戏音量设置。循环背景检查接缝，透明动效检查边缘/遮挡/混合，图集检查帧布局、锚点与播放速率。最后在目标打包构建检查文件随包、加载成本、内存和播放效果，单独播放器通过不算游戏端通过。

## 将声音接进游戏

按用途组织音频：主音量、音乐、对白、音效、环境；游戏设置实际影响混音。使用合适采样率/声道，检查削波、静音头尾、接缝、压缩和播放内存。

3D声音设置衰减、空间化、遮挡与并发；脚步/命中由动画或玩法事件触发并考虑表面。对白与字幕共享稳定 ID 和时间/状态信息，重复触发、被打断、跳过和切场景都能恢复。长配音宜分段，不能一段巨型音频强绑所有游戏事件。

动态音乐按游戏状态切段、交叉淡化或使用真正有用的分轨；不能假设生成模型给出的“stem”都是独立干净乐器。配乐不能压住对白/重要提示。

## 演出边界

H3 生成的是影像，不是可自由绕看的场景、可交互物理或角色骨骼动作。交互段落由 UE 实时运行；AI 视频适合明确的片头/片尾/插入演出等。检查视频切回游戏时的位置、镜头、状态、输入、音频和存档。

精细表演需要表情、嘴形和身体动画，Ming 配音不会自动完成全部口型绑定。用户没有要求完整对白或复杂演出时，优先完成清楚且一致的必要反馈。
