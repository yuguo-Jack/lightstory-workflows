# Product-film authoring

- Read the installed HyperFrames, HyperFrames CLI and GSAP skills before composition edits; use the installed media-use instructions when changing sound or media. Do not install or update agent skills silently. Read `README.md` and `../DESIGN.md` for this film's intent and exact local dependencies.
- Preserve the current 30-second V2, 1920×1080, 30fps plan unless the brief changes. `shots.json` is the narration and shot specification. The 3D scenes are illustrative, not actual inference or gameplay evidence.
- Register one paused root GSAP timeline in `window.__timelines['lightstory-film']`. All visuals, including WebGL, must seek deterministically from that timeline, even when events are suppressed. No runtime fetch, wall-clock animation or unseeded randomness. Timed elements carry explicit start and duration metadata.
- Run the full `hyperframes check` after composition edits; fix errors and review warnings. Inspect actual snapshots of edited scenes and transitions. Render and inspect the MP4, not just the source page.
- Use `hyperframes preview --background` for persistent Studio review. Verify with `preview --status`, retain it through review, and stop explicitly with `preview --stop` when finished. Do not replace it with an unreliable shell background wrapper. Use the Studio project URL, not the raw composition page, for editor handoff.
- Store logs, frame sequences, audio scratch, render caches and browser captures under the repository's ignored `.local/product-video/`. `.hyperframes/` and `node_modules/` are ignored. Preserve source assets, licenses and the approved public film. Never stage scratch files.
- Git staging, commit, push and deployment require authorization in the current user request. The Pages workflow runs manually only. Publish only the approved film and public source; review the exact staged list to exclude scratch and private configuration.
